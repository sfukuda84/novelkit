# novelkit-constitution スキル（W6: 文体の決まり）

作品の最上位の規範を作る。シーン台帳・本文・レビューは、すべてこの文書に従う。条項は、本文を読んで**守れているかを判定できる形**で書く（「読みやすく」ではなく「地の文の 1 文は原則 60 字以内」）。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. モード判定

| 条件 | モード |
|---|---|
| `constitution.md` がなく、`premises.md` がある | **新規** |
| `constitution.md` がなく、既存の本文や設定資料がある（`novelkit.py status` で「シーン台帳にない本文」がある、または README に決まりが書いてある） | **取り込み** |
| `constitution.md` がある | **改訂** |

## 2. 条項の構成

様式は [templates/constitution.md](./templates/constitution.md)。次の節を持つ。

| 節 | 中身 | 主な根拠 |
|---|---|---|
| 1. 語り | 人称、時制、視点人物、視点を切り替える単位（章・話・幕間）、三人称の距離（一元／多元／神視点）、地の文の調子（常体／敬体、硬さ） | N8 |
| 2. 構成の型 | 1 章の型（プロローグ・本章・幕間・エピローグ）、話番号の規則（`<章>-<番号>`、`<章>-P`、`<章>-i<n>`、`<章>-E`）、1 話の字数、各話の末尾に引きを置くか | N9、N2 |
| 3. 表記 | 用字用語の基準（例: 『記者ハンドブック』に準じる、作品固有の表記は `canon/glossary.md`）、数字（漢数字／算用数字）、記号（「……」「――」は 2 つ重ねる、！？の後は全角空白）、ルビの記法、改行と空行、場面の区切り方 | — |
| 4. 禁止事項 | 使わない表現、避ける展開、扱わない題材、描写の上限（暴力・性の表現の水準） | N11、N2 |
| 5. 正典の優先順位 | 食い違ったときに、どのファイルを正とするか（例: 年表 > 人物 > 出来事 > 世界 > 章仕様） | — |
| 6. 声のサンプル | 作者の文体の見本（地の文・台詞・動きの場面・心理の場面から 1〜2 段落ずつ） | 既存の本文、または作者が書いた試し書き |
| 7. モードと AI の関与 | 既定のモード、作者が自分で書く話の基準（例: 山場は作者）、AI の関与の記録方法 | N12 |
| 8. 改訂の記録 | 版、日付、変更点 | — |

- 各条項は **MUST**（違反は CRITICAL）か **SHOULD**（違反は MEDIUM）の印を付ける。
- 条項には ID（`K-1-1` の形）を振る。レビューの指摘で参照するためである。

## 3. 手順

### 新規

1. `premises.md` の N2・N8・N9・N11・N12 から、条項の案を作る。
2. 表記の節は、既定の案（[templates/constitution.md](./templates/constitution.md) の記載）を出発点にし、N2（媒体）に合わせる。Web 連載なら、空行を多めにし、1 段落を短くするなどの方針を SHOULD で置く。
3. 声のサンプル:
   - **通常モード**: 作者に、試し書き（任意の場面を 400〜800 字）を頼む。書く時間がなければ、AI が N8 に沿った見本を 2 案書き、作者に選んでもらう。選ばれた見本は「暫定」と書き、作者の本文ができたら差し替える。
   - **自動モード**: AI が N8 に沿った見本を書き、「暫定（auto）」と書く。
4. 案を示し、条項ごとに MUST／SHOULD の区別と内容を確かめる（通常モード）。影響の大きい論点（人称、時制、表記の方針、禁止事項）は、推奨案つきで質問する。
5. 確定したら `constitution.md` を書き、版を `1.0.0` にする。

### 取り込み

既存作品の決まりを、ファイルを動かさずに移す。

1. 作品の README、引き継ぎ書、設定資料、プロットの冒頭などから、決まりにあたる記述を集める。例: 視点、話番号の規則、正典の優先順位、「通し番号は使わない」などの方針。
2. 本文を 5〜10 本読み、実際の書き方を観察する。人称、時制、記号の使い方、改行、場面の区切り、台詞の書き方などである。書かれた決まりと、本文の実態が違う点は、一覧にして作者に確かめる。
3. 声のサンプルは、既存の本文から引用する。引用元のファイルと行を書く。作者が「この話の文体が理想」と言う話があれば、そこから取る。
4. `python3 <skills>/novelkit-check/scripts/check.py --only prose --metrics` の指標（台詞の比率、漢字の比率、平均文長）を、声の特徴として記録する。
5. 以降は新規の 4〜5 と同じ。

### 改訂

1. 変更点を示し、影響（どの本文・シーン台帳が新しい条項に反するか）を調べる。
2. 作者の了承を得てから改訂する。版を上げる（条項の追加・変更は minor、条項の削除・意味の変更は major）。「改訂の記録」に日付と変更点を書く。
3. 自動モードでは改訂しない。改訂が必要だと判断したら、提案として `auto-decisions.md`（作品の工程なら `docs/`、章の工程なら `chapters/<章>/`）に記録し、見直しの優先度を「高」にする。

## 4. 出力

- `.novelkit/memory/constitution.md`（パスは `config.yaml` の `paths.constitution`）
- 文体の決まりの一部を、`config.yaml` にも反映する（機械検査で拾うため）。

  | 文体の決まり | config.yaml |
  |---|---|
  | 禁止表現（K-1-5・K-4 など） | `prose.banned` |
  | 1 話の字数（K-2-3） | `episode.target_min`、`episode.target_max` |
  | 場面の区切りの数（K-3-7） | `prose.scene_break_max` |

W6 として実行したときは、`W6` のチェックポイントを記録する。改訂のときは、通常のコミット（`docs(novel): 文体の決まりを改訂（vX.Y.Z）`）にする。

## 5. 完了報告

- MUST の条項の要約
- 声のサンプルの出どころ（作者の本文 / 暫定）
- 取り込みのとき: 書かれた決まりと本文の実態の食い違い
- 次の案内: `novelkit-synopsis`（W7）
