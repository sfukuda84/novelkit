# novelkit-status スキル（進捗管理と共通実行規則）

novelkit の工程スキルと統括スキル（`novelkit-bootstrap`、`novelkit-chapter`、`novelkit-write`、`novelkit-all`）が共通で使う。ステップが終わるたびにコミットして進捗を記録し、中断しても、どのスキルからでも続きのステップから再開できる。

## 1. ヘルパースクリプト

```bash
python3 <skills>/novelkit-status/scripts/novelkit.py <command> ...
```

以降、この呼び出しを `$NK` と書く。`<skills>` は、このスキルが置かれた skills ディレクトリ（`.claude/skills`、`.agents/skills`、`.kiro/skills` のいずれか）である。`python3` がない環境では `python` または `py -3` に読み替える。

| コマンド | 用途 |
|---|---|
| `$NK init [--title <作品名>]` | `.novelkit/config.yaml` と作品のディレクトリを作る（既存のものは変えない） |
| `$NK state [--chapter <章>] [--phase work\|outline\|write\|all]` | 完了済みのステップと次のステップを表示する |
| `$NK checkpoint <STEP> "<subject>" [--chapter <章>] [--mode auto\|normal]` | 変更をすべてコミットし、ステップの完了を記録する |
| `$NK next --phase outline\|write\|all [--skip <章,...>]` | 次に着手すべき章とステップを表示する |
| `$NK status` | 作品の工程と、章ごとの進捗（章仕様・シーン台帳・本文・字数）を表で表示する |
| `$NK chapters` / `$NK resolve <query>` | 章の一覧 / 番号や名前から章を決める |
| `$NK context <話番号> [--out <path>]` | 執筆・レビュー用の文脈パックを組み立てる（§5） |
| `$NK ai-usage` | 本文ごとの AI の関与を集計する（§6） |
| `$NK handover [--out <path>]` | 引き継ぎ書を `handover/<日付>.md` に書く |
| `$NK budget [--step <STEP> \| --need <N>]` | 次の工程に、今のセッションの Web 検索の残りが足りるかを判定する（§3「セッションの区切り」） |
| `$NK hooks install` | 作品の `.claude/settings.json` に、Web 検索の回数を数えるフックを登録する（`new_project.py` が自動で行う） |

終了コードは、0 が成功、1 がエラー、3 が前提条件を満たさないこと（章が見つからない、Git リポジトリでないなど）、4 が `budget` の STOP（セッションを区切る）を表す。

## 2. ステップ番号

### 作品の工程（`novelkit-bootstrap`）

| ステップ | 内容 | 担当スキル | チェックポイントの subject |
|---|---|---|---|
| W0 | 事前確認と初期化 | novelkit-bootstrap | （コミットなし） |
| W1 | 種（1 文のコンセプト → ログライン） | novelkit-seed | `docs(novel): W1 種を作成` |
| W2 | 広域調査（類似作品・実例・歴史・トロープ） | novelkit-research-wide | `docs(novel): W2 広域調査` |
| W3 | 方向性の案（3 案の比較と選択） | novelkit-direction | `docs(novel): W3 方向性を選択` |
| W4 | 壁打ち（必須項目 N1〜N12） | novelkit-sparring | `docs(novel): W4 前提を確定` |
| W5 | 焦点調査（考証・一次資料・実在モデルの点検） | novelkit-research-deep | `docs(novel): W5 焦点調査` |
| W6 | 文体の決まり | novelkit-constitution | `docs(novel): W6 文体の決まりを作成` |
| W7 | プロット概要と核の設定 | novelkit-synopsis | `docs(novel): W7 プロット概要と核の設定` |
| W8 | プロットの詳細化（全章の章仕様・伏線台帳・筋の台帳） | novelkit-plot | `docs(novel): W8 プロットを詳細化` |
| W9 | 設定の整理（正典） | novelkit-canon | `docs(novel): W9 設定を整理` |
| W10 | 全体の検証 | novelkit-check | `docs(novel): W10 全体を検証` |

### 章の工程（`novelkit-chapter`・`novelkit-write`・`novelkit-all`）

| ステップ | 内容 | 担当スキル | チェックポイントの subject |
|---|---|---|---|
| C1 | 準備（`$NK state --chapter`） | 統括スキル共通 | （コミットなし） |
| C2 | 1 話ごとのアウトライン（シーン台帳） | novelkit-outline | `docs(<章>): シーン台帳を作成` |
| C3-1 | 矛盾検出 1 回目（重大・カバレッジ） | novelkit-analyze | `docs(<章>): 矛盾を検出（1 回目）` |
| C3-2 | 矛盾検出 2 回目（詳細・時系列・知識状態） | novelkit-analyze | `docs(<章>): 矛盾を検出（2 回目）` |
| C3-3 | 矛盾検出 3 回目（最終確認） | novelkit-analyze | `docs(<章>): 矛盾を検出（3 回目）` |
| C4 | 執筆（1 話ずつ。状態と要約の更新を含む） | novelkit-draft | `draft(<章>): 本文を執筆` |
| C5 | レビュー・物語軸と修正 | novelkit-review（story） | `fix(<章>): 物語軸の指摘を修正` |
| C6 | レビュー・整合軸と修正 | novelkit-review（consistency） | `fix(<章>): 整合軸の指摘を修正` |
| C7 | レビュー・類似性軸（盗作の確認）と修正 | novelkit-review（originality） | `fix(<章>): 類似性軸の指摘を修正` |
| C8 | レビュー・文章軸と修正 | novelkit-review（prose） | `fix(<章>): 文章軸の指摘を修正` |
| C9 | 収束と逆流 | novelkit-converge | `fix(<章>): 仕様に収束・正典に逆流` |
| C10 | 再レビュー（修正の副作用） | novelkit-review（recheck） | `fix(<章>): 再レビューの指摘を修正` |
| C11 | 章の完了 | 統括スキル共通（§3「C11 章の完了」） | `done(<章>): 章を完了` |

`checkpoint` はコミットに trailer `Novelkit-Step: <STEP>` を付け、章の工程では `Novelkit-Chapter: <章>` も付ける。`--mode` を渡すと `Novelkit-Mode: auto|normal` も付ける。変更がないステップも空コミットで記録する。進捗はこの trailer だけから判定する。

`<章>` は `chapters/` の下のディレクトリ名（例: `04-bow-and-partner`）である。

## 3. 共通手順

### 開始時の確認

1. `$NK state`（章の工程では `$NK state --chapter <章> --phase <phase>`）で、完了済みのステップと `NEXT_STEP` を調べる。
2. 完了済みのステップがあれば、`COMPLETED_STEPS` と `NEXT_STEP` をユーザーに示し、`NEXT_STEP` から再開してよいかを確かめる（`--auto` では確かめずに再開する）。ユーザーが別のステップからのやり直しを指示したら、そのステップから進める。完了済みの記録は残したまま、成果物を更新する。
3. 章の工程を始めるときに `WORK_PENDING`（作品の工程の未完了）があれば、ユーザーに示す。W6（文体の決まり）、W8（章仕様）、W9（正典）が未完了のまま章の工程に入ることは勧めない。ユーザーが了承すれば進めてよい。

### 各ステップの終わり

- 1 つのステップが終わったら、必ずチェックポイントを記録する。

  ```bash
  $NK checkpoint <STEP> "<§2 の subject>" [--chapter <章>] --mode <auto|normal>
  ```

- 長いステップ（特に C4 の執筆）の途中では、trailer なしの通常のコミットを作ってよい（例: 1 話書き終えるたびに、本文と、状態・要約・伏線台帳・台帳のチェックの更新を 1 つのコミットにまとめる）。完了の記録は、ステップの最後の `checkpoint` だけで行う。
- `checkpoint` は、既定では変更をすべてコミットする。2 つのステップを並行して進めた場合（例: W5 の調査をサブエージェントに任せている間に W6 を書く）は、`--paths <パス> ...` でそのステップの成果物だけをコミットし、もう一方の成果物を混ぜない。

### セッションの区切り

Web 検索には、1 セッションあたりの回数に上限がある（Claude Code で観測した値は 200 件。公式の記載はない）。サブエージェントの検索も、同じセッションの上限を使う。調査（W2・W5）と類似性軸（C7）は検索が多いので、次の規則でセッションを区切る。**区切りは工程の境目に置き、工程の途中で上限に当たって未完了が残らないようにする。**

#### 規則 1: 必ず区切る場所（どの環境でも）

| 場所 | すること |
|---|---|
| 作品の工程の後（W10 の後） | `config.yaml` の `session.stop_after_work` が true（既定）なら、章の工程に進まずに止まる。完了報告で「新しいセッションで `novelkit-all` を実行する」と案内する。自動モードでも止まる |
| 章と章の間（C11 の後） | 回数を数えられない環境（`budget` が UNMETERED）では、`session.chapters_unmetered`（既定 1）章を終えたら止まる |

#### 規則 2: 回数を数えて止まる場所（Claude Code でフックがあるとき）

作品を作るとき（`new_project.py`）に、`.claude/settings.json` にフックが登録される。フックはセッションごとの Web 検索の回数を `.novelkit/usage/` に記録する。次の場所で `$NK budget` を実行する。

| 場所 | コマンド |
|---|---|
| W2（広域調査）の前 | `$NK budget --step W2` |
| W5（焦点調査）の前 | `$NK budget --step W5` |
| 章に入る前（C2 の前、または途中の章の再開の前） | `$NK budget --step chapter` |
| C7（類似性軸）の前 | `$NK budget --step C7` |
| そのほか、検索の多い作業を単独で始める前 | `$NK budget --need <見積もり>` |

| 結果 | すること |
|---|---|
| `VERDICT: OK` | 続ける |
| `VERDICT: STOP`（終了コード 4） | その工程に入らずに止まる。それまでのステップのチェックポイントは記録済みなので、新しいセッションで同じスキルを同じ引数で実行すれば、続きから再開する。完了報告に、止まった理由（使用数・残り・見積もり）と再開のコマンドを書く。**自動モードでも止まる**。これは失敗ではなく、区切りである |
| `VERDICT: UNMETERED` | 規則 1 だけに従う |

- 見積もりは `config.yaml` の `session.estimates` で変える。実績が見積もりと大きく違ったら、見積もりを直す。
- 同じ作品で 2 つのセッションを同時に開くと、後から開いた方が「今のセッション」になる。同時に開かない。
- 規則 2 で止まらずに工程の途中で上限に当たった場合（見積もりの外れ）は、その工程を完了にせず、未検索の範囲を記録して止まる（`novelkit-review` の類似性軸の手順 8 と同じ扱い）。

### サブエージェントに任せるとき

調査（W2・W5）や物語軸の読み手（C5・C10）のように、工程の一部をサブエージェントに任せる場合は、次のように分担する。

| 担当 | すること |
|---|---|
| サブエージェント | そのスキルの SKILL.md とテンプレートを読み、手順どおりに成果物を書く。**指定されたファイル以外は編集しない。** 最終回答で、要点と、自動モードで記録すべき判断と、手順どおりに進めにくかった点を返す |
| 親（呼び出した側） | `auto-decisions.md` への記録、成果物の確認、前提との食い違いの反映、チェックポイントのコミット |

- サブエージェントへの指示には、作品のディレクトリ、読むべき SKILL.md、書いてよいファイル、書いてはいけないファイル（`auto-decisions.md` とコミットは親が行う）を明示する。
- 物語軸の読み手には、**本文以外のファイルを開かない**ことを明示する（`novelkit-review` §3）。
- サブエージェントの報告の中の事実（件数、作品名、判定）は、成果物のファイルで確かめてから使う。

### C11 章の完了

1. `python3 <skills>/novelkit-check/scripts/check.py --chapter <章>` を実行し、ERROR が 0 件であることを確かめる。
2. シーン台帳に、未完了の話（`[人]` 以外）と未完了の収束タスクがないことを確かめる。残っていれば一覧を示し、C4・C9 に戻って片付けるか、残したまま完了とするかを確かめる（`--auto` では戻って片付ける）。
3. 通常モードでは、本文が `status: 下書き` のままの話を一覧にして示す。作者が推敲を終えていなければ、「下書きのまま章を完了にする（後で推敲する）」か「推敲を待つ」かを確かめる。
4. `$NK handover` で引き継ぎ書を書く。
5. `$NK checkpoint C11 "done(<章>): 章を完了" --chapter <章> --mode <auto|normal>` を記録する。

### ブランチ

- 既定では、今のブランチ（通常は `main`）の上で直列に進める。worktree は使わない。正典を全章で共有するため、章を並行して進めると衝突しやすい。
- 章ごとにブランチを分けたい場合は、ユーザーの指示があるときだけ `git switch -c chapter/<章>` で分け、C11 の後にマージする。

## 4. モード

novelkit のスキルは、次の 2 つのモードで動く。引数に `--auto` があれば自動モードである。なければ、文体の決まりの K-7-1（既定のモード）に従い、K-7-1 がなければ通常モードである。`novelkit-bootstrap` の一括質問モード（`--oneshot`）は、最初の質問の後は自動モードとして扱う（チェックポイントの `--mode` は `auto`）。

| | 通常モード（既定） | 自動モード（`--auto`） |
|---|---|---|
| 本文 | **AI が下書きを書く。** 作者が推敲し、確定させる。下書きの間は `status: 下書き`、`ai: AI本文`。作者が推敲して確定したら `status: 確定`、`ai: AI下書き→作者推敲` にする | **AI が本文まで書き、確定させる。** `status: 確定`、`ai: AI本文` |
| 質問 | 判断が要る論点は、推奨案（`**Recommended:**`）を添えて質問し、合意を得てから進める。1 回の質問は 4 問まで | 質問しない。推奨案を採用して進め、`auto-decisions.md` に記録する |
| 承認 | 工程の成果物（案の選択、分割案、シーン台帳など）は、書き出す前に提示して承認を得る | 提示せずに書き出し、完了報告に載せる |
| `[人]` の話 | 作者が書く話。AI は書かず、完了にもしない | 新しくは付けない。通常モードで付けた `[人]` が台帳に残っていれば、自動モードでも書かず、完了にもせず、完了報告に挙げる |

### 自動モードの記録

自動で決めたことは、すべて記録する。後から見直せるようにするためである。

- 作品の工程（W1〜W10）の判断は `docs/auto-decisions.md`、章の工程（C2〜C11）の判断は `chapters/<章>/auto-decisions.md` に追記する。章の工程から呼ばれた `novelkit-canon`（逆流）や `novelkit-check` の判断も、その章のファイルに書く。
- 1 件ごとに次を書く。
  - ステップ、論点、採用した案、ほかの選択肢、理由
  - 根拠の種類（ユーザーの入力 / 調査 / 推測）
  - 見直しの優先度（高 / 中 / 低）
  - 反映したファイル
- **見直しの優先度を「高」にするもの**: 結末、主要人物の生死、主人公の目的と欠落、ジャンルと読者、正典の改変、文体の決まり、根拠が推測だけのもの。
- 質疑の記録（`premises.md`、`spec.md` の Clarifications）では、見出しに `(auto)` を付け、回答の頭に `(auto: 仮定)` を付ける。

### 自動モードでも止まる場面

- Git リポジトリでない、または未コミットの変更がある（開始時）
- `check.py` の ERROR が、同じ原因に対して 3 回直しても 0 件にならない
- 実在の人物・団体を特定できる形で描き、名誉やプライバシーを損なうおそれがあると判定した（`novelkit-research-deep`、`novelkit-review` の整合軸）
- 既存作品と表現が一致する文が、書き直しても残る。または、特定の作品と核（中心の考え・結末）の展開の組み合わせが重なる（`novelkit-review` の類似性軸）
- 種（W1）の入力がなく、何を書くかが決められない
- 投稿先・応募先の規定に反するおそれがある（`novelkit-publish`）
- セッションの区切り（§3「セッションの区切り」の規則 1・2）。これは失敗ではない。新しいセッションで同じスキルを実行すれば、続きから再開する

止まったら、止まった理由、止まったステップ、ユーザーに判断してほしい事項（選択肢と推奨案）を報告して終了する。判断の後に同じスキルを実行すれば（モードの指定は問わない）、続きのステップから再開できる。

## 5. 文脈パック（`$NK context`）

執筆（C4）とレビュー（C5〜C8、C10）では、本文を書く・読む前に、その話の文脈パックを組み立てて読む。正典や過去の本文をすべて読むと文脈があふれるので、その話に必要なものだけを集める。

| 入るもの | 範囲 |
|---|---|
| 文体の決まり | 全文 |
| この話のシーン台帳 | その話のブロック |
| 章仕様 | 「章の役割」と、その話が担う ID（EV・IR など）の行 |
| この話で伏せるもの | `reveal_from` がこの話より後の正典の項目の、伏せる名前 |
| 正典 | `ai: always` の項目と、シーン台帳のブロックに名前・別名が出る `ai: mention` の項目。`ai: never` は入れない |
| 伏線・約束 | この話が張る・進める・回収するもの |
| 状態 | 直前の話の終了時点（`state.md`） |
| 過去の話 | 同じ章の直前の話（既定 2 話）は本文。それより前は要約（`summaries.md`） |

- 出力先は `chapters/<章>/context/<話番号>.md` にする（`--out`）。このディレクトリは生成物なので、`.gitignore` に入れてよい。
- シーン台帳の「登場」に人物を漏れなく書くと、正典が正しく入る。自動で拾えない項目は、シーン台帳のブロックに名前を書き足してから組み立て直す。

## 6. AI の関与の記録（`$NK ai-usage`）

本文のフロントマターの `ai:` に、話ごとの AI の関与を書く。投稿サイトや公募の申告に使う。

| 値 | 意味 |
|---|---|
| `AI本文` | AI が書いた本文。自動モードで確定したもの、または通常モードでまだ作者が推敲していない下書き |
| `AI下書き→作者推敲` | AI の下書きを、作者が推敲して確定した（確定のときに `AI本文` から書き換える） |
| `作者執筆＋AI補助` | 作者が書き、AI はレビュー・校正・アイデア出しだけを行った |
| `AI不使用` | AI を使っていない |

`$NK ai-usage` は、`status: 下書き` の本文を別に一覧にする。申告の区分は投稿先ごとに違い、規約も変わる。区分の決め方は `novelkit-publish` で、公式の規約を参照日つきで確かめて決める。

## 7. 共通規則

- **破壊的コマンドの禁止**: `rm -rf`、`git reset --hard`、`git clean -f`、`git push --force` を使わない。本文や正典を消すときは、ユーザーの了承を得る。
- **作者の本文を守る**: `status: 確定` の本文と、`[人]` の話の本文を、AI の判断だけで書き換えない。直したほうがよい箇所は、指摘と修正案として示す。自動モードで AI が書いた本文は、この限りでない。
- **出典**: 調査の事実には出典 URL と参照日を付ける。出典のない事実を書かない。
- **言語**: 応答と成果物は日本語で書く（`.kiro/steering/language.md`）。
- **質問のツール**: `AskUserQuestion` は Claude Code のツール名である。ほかのエージェントでは同じ働きのツールを使い、なければ選択肢と推奨案を文章で示して回答を待つ。

## 8. 手動での利用

ユーザーからこのスキルを直接呼ばれたときは、引数に応じて次を行う。

- `status`（または引数なし）: `$NK status` の結果を表示し、次に使うスキルを案内する。
- `state` / `next` / `chapters` / `resolve`: 結果を表示する。
- `context <話番号>`: 文脈パックを作り、保存先と大きさを報告する。
- `ai-usage`: 結果を表示する。記録のない本文があれば、`ai:` を書き足すよう案内する。
- `handover`: 引き継ぎ書を書き、次にやることを 1〜3 個に絞って添える。
- `finish <章>`: §3「C11 章の完了」の手順に従う。
