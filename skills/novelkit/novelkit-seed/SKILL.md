# novelkit-seed スキル（W1: 種 → ログライン）

ユーザーの 1 文を、以降の調査と方向性の検討に使える形にする。まだ何も決めない。**入力の 1 文は一字も変えずに残す。**

進捗の記録、モード（通常 / `--auto`）、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 引数

```text
$ARGUMENTS
```

- `--auto` を取り除いた残りを、種の 1 文として扱う。
- 引数がなく、`docs/concept/seed.md` もなければ、次のように聞く（自動モードでは止まる。`novelkit-status` §4）。

  > 書きたい話を 1 文で教えてください。「〜が〜する話」でも、場面の断片でも、題名だけでも構いません。発表先（Web 連載／公募／同人）が決まっていれば、それも添えてください。

- `seed.md` がすでにあれば、原文を残したまま「追記（日付）」の節を足す。

## 2. 手順

1. **原文を記録する。** 引数の 1 文を、そのまま `seed.md` の「原文」に書く。
2. **要素を分ける。** 原文から読み取れることを、次の表に分ける。原文にないものは「未定」と書き、推測で埋めない。

   | 要素 | 内容 |
   |---|---|
   | 主人公 | |
   | 欲しいもの・目的 | |
   | 障害・敵対 | |
   | 舞台（時代・場所） | |
   | ジャンルの手がかり | |
   | 発表先・読者の手がかり | |

3. **「もしも〜なら」に言い換える。** 原文を、状況を問う形に 3 通り言い換える（スティーヴン・キングの what if）。1 つは原文に忠実に、残り 2 つは視点・立場・状況のどれかをずらす。
4. **ログラインの案を 3 つ作る。** 各案は 1〜2 文で、主人公・目的・障害・賭けられているものを含める。3 つの案は、ジャンルか焦点（誰の物語か、何が賭けられているか）を変える。
5. **4 条件で採点する。** 各案を次の 4 条件で ◎／○／△ に評価し、弱い条件をどう強くするかを 1 行で添える。

   | 条件 | 見るもの |
   |---|---|
   | 皮肉・意外性 | 設定の中に、逆説や意外な組み合わせがあるか |
   | 全体像が浮かぶ | 読んだだけで、場面と展開が思い浮かぶか |
   | 誰向けで規模は | 想定読者と話の大きさ（1 冊／長期連載）が分かるか |
   | 題が中身を語る | 仮の題が、何の話かを伝えているか（各案に仮題を付ける） |

6. **エレベーターピッチを書く。** 最も評価の高い案を、50 字程度・30 秒で話せる長さの売り込みにする。
7. **調査の論点を挙げる。** W2（広域調査）で調べるべきことを 5〜10 個挙げる。類似しそうな作品の系統、題材の現実の事例、歴史的な背景など。
8. `seed.md` を書き、ユーザーに提示する。

### 通常モード

- 3 案のうち、どれを調査の軸にするかを質問する。1 つに絞らず「全部を材料に調べる」も選べる。推奨案を先頭に置く。
- 回答を `seed.md` の「選択」に書く。

### 自動モード

- 採点が最も高い案を調査の軸にし、`docs/auto-decisions.md` に記録する（見直しの優先度: 中）。`seed.md` の「選択」には、`(auto)` と理由を書く（例: 「調査の軸: A（auto）。理由: 採点が最も高く、原文に忠実」）。

## 3. 出力

`docs/concept/seed.md`（様式: [templates/seed.md](./templates/seed.md)）

終わったら `novelkit-status` の手順で `W1` のチェックポイントを記録する（単独で実行したときも記録する）。

## 4. 完了報告

- 原文、選んだログラインと仮題、エレベーターピッチ
- 調査の論点
- 次の案内: `novelkit-research-wide`（W2）
