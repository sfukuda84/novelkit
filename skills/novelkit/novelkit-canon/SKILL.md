# novelkit-canon スキル（W9: 設定の整理 → 正典）

正典は、全章が共有する唯一の事実の置き場である（speckit の共通基盤とデータモデルに当たる）。**「使わない 100 項目より、実際に引く 10 項目」**を原則にし、物語で使う項目だけを持つ。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 正典の構成

| ファイル | 中身 | 様式 |
|---|---|---|
| `canon/README.md` | 索引。人物の一覧と、口調の早見表（一人一癖表） | [templates/README.md](./templates/README.md) |
| `canon/character/<名前>.md` | 人物。1 人 1 ファイル | [templates/character.md](./templates/character.md) |
| `canon/place/<名前>.md` | 場所 | [templates/place.md](./templates/place.md) |
| `canon/org/<名前>.md` | 組織・勢力 | [templates/org.md](./templates/org.md) |
| `canon/item/<名前>.md` | 物語で働くアイテム | [templates/item.md](./templates/item.md) |
| `canon/rules.md` | 世界の規則（魔法・技術・制度） | [templates/rules.md](./templates/rules.md) |
| `canon/glossary.md` | 用語集と表記の統一表 | [templates/glossary.md](./templates/glossary.md) |
| `canon/timeline.md` | 年表。作中の時系列と掲載順 | [templates/timeline.md](./templates/timeline.md) |
| `canon/relations.md` | 関係図と、関係が変わる時点 | [templates/relations.md](./templates/relations.md) |

### フロントマター（機械が読む欄）

人物・場所・組織・アイテムのファイルは、先頭に次のフロントマターを持つ。

```yaml
---
name: エレオノーラ            # 正式な名前（正表記）
type: character               # character / place / org / item / term / rule / culture / other
aliases: [母, 戦乙女]         # 別名・呼び名。文脈パックで、この名前が出たら項目を渡す
ai: always                    # always（常に渡す）/ mention（名前が出たら渡す）/ never（渡さない）
reveal_from: 第8章            # 任意。この話（例: 8-12）または章（第8章）より前の本文に hidden_names を出さない
hidden_names: [ハガン]        # 任意。省略時は reveal_from があれば name を伏せる
born: -24                     # 任意（人物）。作中年での生年。年齢は計算で出す
variants: [エレオノーレ]      # 任意。表記の揺れ。本文に出たら警告する
---
```

- **ai の決め方**:
  - `always`: 主人公と、ほぼ全話に出る人物・規則
  - `mention`: それ以外（既定）
  - `never`: 作者のメモ、真相の詳細など、執筆の文脈に入れると漏れやすいもの
- **reveal_from**: 読者に名前を伏せる人物・用語に付ける。伏せる間の呼び方（例: 「王」）は `aliases` に入れる。
  - 明かす章のシーン台帳がまだないうちは、章で書く（`第8章`）。その章より前の話では、すべて伏せる扱いになる。
  - 明かす章の C2（アウトライン）で、話番号（`8-12`）に書き換える。話番号の形で書いたのに、その章の台帳にない話番号なら、`check.py` が ERROR にする。
- **born と作中年**: 年表で「作中年」の基準（例: 主人公の誕生を 0 年）を決め、人物の `born` をその基準で書く。シーン台帳の各話に `作中年` と `年齢` を書くと、`check.py` が年齢を検証する。
- 本文（フロントマターより下）には、AI が知るべきことだけを書く。人間向けのメモは「作者メモ」の節に分け、`ai: never` の別ファイルにしてもよい。

## 2. モード

| 条件 | モード | 手順 |
|---|---|---|
| W9 として実行（核の設定だけがある） | **整理** | §3 |
| `--adopt <dir>` がある | **取り込み** | §4 |
| `novelkit-converge` から呼ばれた、または「本文に合わせて正典を直して」と言われた | **逆流** | §5 |

## 3. 整理（W9）

1. **材料を集める。** 次を読み、登場するすべての固有名詞・年代・規則を抜き出す。
   - `synopsis.md`、`structure.md`、全章の `spec.md`、`promises.md`
   - `docs/research/deep/`、`anachronism.md`
   - 核の設定（`canon/character/`、`rules.md`）
2. **項目にする基準**を当てる。2 つ以上の章に出る、本文で名前を呼ばれる、規則として場面を縛る、のどれかに当たるものだけを項目にする。当たらないものは、章仕様の中に書いたままにする。
3. **人物を仕上げる。** 核の欄（Ghost・Lie・Want・Need・Truth、変化）に加えて、次を埋める。
   - 外見
   - 口調（一人称・二人称・語尾・口癖）
   - 誰を何と呼ぶか
   - 秘密と開示の時点
   - 履歴（年表の出来事への参照）
   - 物語での働き
4. **年表を作る。**
   - 作中年の基準を決める。
   - 出来事を、作中の時系列で並べる。各出来事に、関わった人物と、掲載順のどの章・話で読者に見せるか（回想なら、その話）を書く。
   - 人物の生年を `born` に書く。
5. **用語集を作る。**
   - 固有名詞と作品独自の用語について、正表記、読み、ルビの要否、揺れの候補、初出の章を書く。
   - 文体の決まりの表記の方針（数字・記号・用字）で、作品固有の例外があればここに書く。
6. **関係図を作る。** 主要人物の関係と、関係が変わる章を表にする。関係が場面ごとに変わる作品では、「時点」の列を設ける。
7. **伏せるものを設定する。** 章仕様の IR で「伏せる」とした名前・用語に、`reveal_from` と `hidden_names` を付ける。この時点では話番号がないので、`reveal_from` は明かす章（`第N章`）で書く。**空にしない**（空だと伏せる扱いにならない）。
8. **索引と早見表**（`canon/README.md`）を作る。口調の早見表は、執筆のときに必ず引く。
9. **検証する。** `check.py --only canon,structure` を実行し、ERROR を 0 件にする。名前・別名の重複の警告は、意図どおりか確かめる。
10. **提示する。**
    - **通常モード**: 項目の一覧と、判断が要る点を推奨案つきで確かめる。判断が要る点とは、作中年の基準、伏せる名前、名前の表記などである。
    - **自動モード**: 推奨案のまま書き出す。伏せる名前と作中年の基準は、`docs/auto-decisions.md` に見直しの優先度「中」で記録する。

## 4. 取り込み（`--adopt`）

既存作品の設定資料を、正典として使えるようにする。**元のファイルは動かさない。**

1. `config.yaml` の `paths.canon` を、既存の設定ディレクトリに向けるか、`canon/` を新しく作るかを決める。通常モードでは作者に確かめる。推奨は「既存のディレクトリに向け、フロントマターだけを足す」。
2. 既存の人物ファイルなどの先頭に、§1 のフロントマターを足す。本文は変えない。足す前に差分を示して了承を得る（自動モードでは足して、一覧を報告する）。
3. 既存の年表・用語の資料から、`timeline.md`・`glossary.md` の形の表を作る。既存の資料が正典の優先順位で上なら、新しい表は既存の資料を参照する形にして、内容を二重に持たない。
4. 食い違い（年齢、表記、呼び名）を一覧にし、どちらを正とするかを確かめる。

## 5. 逆流（本文 → 正典）

執筆で生まれた事実を正典に書き戻す。`novelkit-converge` から呼ばれる。

1. 対象の本文とシーン台帳から、正典にない新しい事実を抜き出す。新しい人物・場所・用語、人物の新しい過去や癖、関係の変化などである。
2. 正典と食い違う事実は、次の 3 つに分ける。

   | 分類 | 扱い |
   |---|---|
   | 本文の誤り | 本文を直す（converge が扱う） |
   | 本文の方が良い | 正典を直す |
   | 判断が要る | 作者に聞く |

3. 正典を直す前に、影響を調べる。その事実に依存する後続の章の `spec.md`・`scenes.md`・本文である。
4. **通常モード**: 差分と影響を示し、承認を得てから反映する。**自動モード**: 反映し、正典の改変を、呼び出した章の `chapters/<章>/auto-decisions.md` に見直しの優先度「高」で記録する。
5. 変更した項目の本文の末尾に「変更の記録」（日付、話番号、内容）を足す。

## 6. 出力

`canon/` 一式（§1）。W9 として実行したときは `W9` のチェックポイントを記録する。取り込みと逆流では、通常のコミットにする。

## 7. 完了報告

- 項目の件数（種類ごと）と、`ai: always` の項目
- 伏せる名前と、その開示の話
- 作中年の基準
- 検証の結果
- 次の案内: `novelkit-check`（W10）、その後 `novelkit-chapter`（章の工程）
