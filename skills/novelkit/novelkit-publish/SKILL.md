# novelkit-publish スキル（公開・応募の準備）

作品を、投稿先・応募先の規定に合わせて出せる状態にする。**規約と規定は変わる。このスキルは規定の中身を持たず、実行のたびに公式のページで確かめる。**

進捗の記録、モード、AI の関与の記録は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 入力

- 引数の投稿先・応募先。なければ `premises.md` の N2（発表先）
- `docs/concept/seed.md`・`direction.md`・`premises.md`、`docs/plot/synopsis.md`
- 本文と、`novelkit.py ai-usage` の結果

## 2. 手順

### ステップ 1: 規定を確かめる

投稿先・応募先ごとに、公式のページ（利用規約、投稿ガイドライン、ヘルプ、募集要項）を WebSearch / WebFetch で確かめ、`publish/<投稿先>/rules.md` に参照日つきで書く。

| 確かめること | 例 |
|---|---|
| タイトル・キャッチコピー・あらすじ（紹介文）の字数と、使えない記法 | ルビが使えない欄 |
| タグ・キーワードの数と字数、必須のタグ | 年齢制限のタグ |
| 1 話の字数の上限・下限（あれば） | |
| 生成 AI の利用の申告の区分と方法、禁止事項 | 申告の区分、タグ、AI 生成作品の扱い、コンテストへの参加条件 |
| 公募: 原稿の形式、梗概の字数と「結末まで書く」の要否、AI 利用の可否と記載方法、応募の締切 | |

- 公式のページを開けなかった場合は、その旨を書く。二次情報（まとめ記事など）だけに基づく事項は「要確認」とし、作者に公式での確認を頼む。
- 前回確かめた日付から 1 か月以上たっていたら、確かめ直す。

### ステップ 2: AI の関与の申告

1. `python3 <skills>/novelkit-status/scripts/novelkit.py ai-usage` を実行し、本文ごとの関与を集計する。記録のない本文があれば、作者に確かめて `ai:` を書き足す。
2. ステップ 1 の規定の区分に、集計を当てはめる。作品全体で最も強い関与を基準にするか、話ごとに申告するかは、規定に従う。
3. 当てはめた区分と根拠（規定の該当箇所、参照日）を `publish/<投稿先>/ai-disclosure.md` に書く。
4. **規定に反するおそれがある場合**（例: AI の本文利用が認められない公募に、`AI本文` の話がある）は、応募を勧めず、作者に報告する。自動モードでも止まる。

### ステップ 3: 類似性の最終確認

公開・応募の前に、全章の類似性軸（`novelkit-review originality`）が済んでいるかを確かめる。済んでいない章があれば、先に実行する。題名の案（ステップ 4）も、同じ題の既存作品がないかを検索する。

### ステップ 4: 案を作る

`publish/<投稿先>/` に、次の案を作る（様式: [templates/listing.md](./templates/listing.md)）。

- **タイトル**: 3 案。中身が伝わるか、類似作品と紛れないか（`wide.md` で確かめる）
- **キャッチコピー**: 3 案。規定の字数以内
- **あらすじ（紹介文）**: 冒頭の 1〜2 文で、主人公・状況・引きを示す。結末は書かない（投稿サイトの場合）
- **タグ**:
  - 定番のタグ（ジャンル、年齢制限、読者が検索する語）
  - あらすじで触れていない重要な要素
  - 否定形のタグ（「〜なし」）は避ける
  - 規定の数以内にする
- **公募用の梗概**: 規定の字数（多くは 800 字程度）で、結末まで書く。ぼかさない。字数と「結末を含むこと」を確かめる。

### ステップ 5: 提示

- **通常モード**: 案を示し、選んでもらう。選んだものを `listing.md` の「採用」に書く。
- **自動モード**: 推奨案を採用し、`docs/auto-decisions.md` に記録する。AI の関与の申告区分は、見直しの優先度を「高」にする。

**投稿・応募そのもの（サイトへの入力、送信）は行わない。** 作者が行う。

## 3. 出力

- `publish/<投稿先>/rules.md`（規定と参照日）
- `publish/<投稿先>/ai-disclosure.md`（申告の区分と根拠）
- `publish/<投稿先>/listing.md`（タイトル・キャッチコピー・あらすじ・タグ・梗概）

通常のコミットにする（`docs(publish): <投稿先> の準備`）。

## 4. 完了報告

- 規定の要点と参照日（要確認の事項を先に）
- AI の関与の集計と、申告の区分
- 採用した（または推奨する）タイトル・キャッチコピー・タグ
- 作者が行うこと（投稿・応募、公式での確認）
