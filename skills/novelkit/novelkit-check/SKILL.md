# novelkit-check スキル（W10: 機械検証）

機械で判定できる不整合を、読んで判断する前に取り除く。**ERROR は直す。WARN は内容を確かめ、意図どおりなら報告に書く。**

## 1. 実行

```bash
python3 <skills>/novelkit-check/scripts/check.py [--root <作品>] [--only <分類,...>] [--chapter <章>] [--episode <話番号>] [--metrics]
```

`<skills>` は、このスキルが置かれた skills ディレクトリである。終了コードは、ERROR があれば 1、なければ 0。

| 分類 | 検査すること | 主な ERROR |
|---|---|---|
| `structure` | シーン台帳のタスク ID と話番号の重複、話番号と章の一致、「視点」「変わること」「引き」の有無、完了の話に本文があるか、章仕様の ID の参照先とカバレッジ | 必須イベント（EV）を担う話がない、完了 [x] なのに本文がない |
| `canon` | 正典の `type`・`ai` の値、名前・別名の重複、`reveal_from` の形と参照先、シーン台帳の `年齢` と「作中年 − 生年（born）」の一致、本文の「名前（N歳）」。年表（timeline.md）そのものは読まない | 年齢が合わない |
| `reveal` | `reveal_from` より前の話の本文に、伏せる名前（`hidden_names`）が出ていないか | 伏せる名前の早漏れ |
| `promises` | `promises.md` の ID の重複、シーン台帳の「伏線」「約束」の参照先、回収予定を過ぎた未回収 | 参照先がない |
| `threads` | `threads.md` の種類（M/I/C/E）、開く前に閉じていないか、入れ子の交差（「意図」を書いた行は除く）、シーン台帳の「筋」の参照先 | 種類が不正、参照先がない |
| `length` | 1 話の字数と、シーン台帳の「目安」（±`episode.tolerance`）または既定の範囲 | — |
| `prose` | 文末の連続、長い文、指示語の密度、括弧の対応、三点リーダ・ダッシュ、！？の後の空白、禁止表現、場面区切りの数 | — |
| `glossary` | `canon/glossary.md` の「揺れ」と、正典の `variants` が本文に出ていないか | — |

- しきい値は `.novelkit/config.yaml` の `episode` と `prose` で変える。文体として意図したもの（過去形の「た。」が続く、など）で警告が多すぎる場合は、しきい値を上げてよい。上げたら、その理由を文体の決まりに書く。
- `--metrics` を付けると、本文ごとの台詞の比率、漢字の比率、地の文の平均文長を INFO で出す。文体の決まりの「声のサンプル」の指標と比べるのに使う。
- `--chapter` と `--episode` は、検査全体をその範囲に絞る。作品全体に関わる検査（正典の定義、伏線・筋の台帳の全体）は、範囲を絞ったときは省く。W10 と、章の完了の前には、範囲を絞らずにも一度実行する。
- `--draft-dir <dir>` を付けると、シーン台帳を使わずに、そのディレクトリの `.md` を本文として検査する（`length`・`prose`・`glossary`・`canon` だけ）。既存作品を取り込む前の診断に使う。

## 2. 手順

1. 目的に合わせて範囲を決める。

   | 場面 | 範囲 |
   |---|---|
   | W10（作品の工程の最後） | 全分類 |
   | C3（矛盾検出） | `structure,canon,promises,threads` |
   | C4 の各話の後 | `--episode <話番号>` |
   | C8（文章軸） | `--chapter <章> --only prose,glossary,length` |
   | C11（章の完了） | `--chapter <章>` |

2. 実行し、ERROR を 1 件ずつ直す。
   - 直す場所は、正典の優先順位（文体の決まりの 5. 正典の優先順位）に従って決める。年表と本文の年齢が食い違うなら、原則として年表が正で、本文を直す。
   - 本文を直すときは `novelkit-status` §7「作者の本文を守る」に従う。`status: 確定` の本文と `[人]` の話は、通常モードでは修正案を示して了承を得る。
3. もう一度実行し、ERROR が 0 件になるまで繰り返す。同じ原因で 3 回直しても 0 件にならなければ、止まって報告する（自動モードでも止まる）。
4. WARN を種類ごとにまとめ、意図どおりのもの・直すもの・しきい値を変えるものに分ける。
   - **通常モード**: 分け方を示して確かめる。
   - **自動モード**: 直すものは直し、しきい値の変更は提案として `auto-decisions.md` に書く（自動では変えない）。W10 では `docs/auto-decisions.md`、章の工程では `chapters/<章>/auto-decisions.md` に書く。

## 3. 出力

- 検証の結果（ERROR・WARN の件数と内容）を完了報告に書く。W10 では `docs/check-report.md` にも保存する。
- W10 として実行したときは、`W10` のチェックポイントを記録する。

## 4. 完了報告

- ERROR と WARN の件数、直したもの、意図どおりとした WARN
- 次の案内: W10 の後は `novelkit-chapter`（最初の章のアウトライン）。`novelkit.py next --phase outline` で最初の章を示す
