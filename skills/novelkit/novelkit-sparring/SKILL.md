# novelkit-sparring スキル（W4: 壁打ち → 前提の確定）

方向性を、プロットを書き始められる前提に変える。**推測で埋めない。必須項目が全部埋まるまで続ける**（speckit-concept-2-feature のヒアリングと同じ原則）。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 0. 大原則

- 前提の根拠にしてよいのは、次の 3 つだけである。
  - (a) `seed.md`・`direction.md` に書かれたユーザーの決定
  - (b) このスキルでのユーザーの回答
  - (c) 自動モードで採用した推奨案。`(auto: 仮定)` と明示する
- 調査の結果（`wide.md`）は、**選択肢と推奨案の材料**である。ユーザーが採用して、初めて根拠になる。
- 1 回の質問は 4 問まで。**1 問ずつ深掘りする**のが基本で、関連の強い論点だけをまとめて聞く。
- 採らなかった案は、消さずに `backlog.md` に残す。

## 1. 役の選び方

演じる小説家エージェントを、引数または `direction.md` のジャンルから決める。

| 引数の例 | エージェント |
|---|---|
| `ln`、`ラノベ`、`なろう`、`web小説` | `novelist-ln` |
| `literary`、`文芸`、`純文学` | `novelist-literary` |
| `mystery`、`ミステリ`、`サスペンス` | `novelist-mystery` |
| `sf`、`ファンタジー`、`異世界` | `novelist-sf` |

1. `~/.myai/sparring/agents/<エージェント>.md` と、その定義が指す共通規範（`~/.myai/sparring/common-persona/novelist.md`）があれば読む。フロントマターより下の本文を、この会話での振る舞いの指示として採用する。衝突したらジャンル側を優先する。
2. 読めなければ、その旨を伝えたうえで、次の要点で進める。
   - まず診断し、次に改善する。
   - 良い部分も同じ精度で言う。
   - 指摘には必ず代替案を付ける。
   - 最後に「次に決めること」を 1〜3 個に絞る。
3. ジャンルが曖昧なら、推定して一言確認するだけにする。ジャンルを問う質問から始めない。

## 2. 必須項目

`premises.md` の充足状況表で、各項目の状態を **確定 / 対象外 / 未決** で管理する。`seed.md`・`direction.md` に具体的に書いてある項目は、出典を記録して「確定」にし、聞かない。

| ID | 項目 | 埋まったと言える状態 |
|---|---|---|
| N1 | ログライン | 4 条件（皮肉・全体像・誰向けと規模・題）を満たす 1〜2 文と、仮題がある |
| N2 | 媒体と読者 | 発表先（Web 連載／公募／同人／その他）、想定読者、1 話の字数、更新頻度（連載の場合）が決まっている |
| N3 | ジャンルと約束事 | ジャンル、約束事、必須シーンが列挙されている |
| N4 | 中心の考え | 物語を通して変わる価値が 1 文で言える |
| N5 | 主人公のアーク | 主人公の名前（仮でよい）・年齢と、Ghost（過去の傷）・Lie（誤った思い込み）・Want（欲しいもの）・Need（本当に必要なもの）・Truth（最後に得る真実）が言える |
| N6 | 敵対と葛藤 | 敵対者（人・状況・自分）と、その言い分が言える |
| N7 | 結末 | 最後の場面と、主人公が最後に選ぶことが決まっている |
| N8 | 視点と文体 | 人称、時制、視点人物、視点を切り替えるか、地の文の調子（常体／敬体、硬さ）が決まっている |
| N9 | 分量と構成の型 | 総字数、章の数、1 章の話数、構成の型（三幕構成、Save the Cat、7 ポイント、起承転結、序破急、ヒーローズ・ジャーニーなど）、1 章の型（プロローグ・幕間・エピローグの有無）が決まっている |
| N10 | 世界の核 | 物語が成り立つのに必要な規則（魔法・技術・制度・社会）だけが挙がっている |
| N11 | 売りとやらないこと | 類似作品に対する勝ち筋、主なトロープの扱い方、意図的に外すお約束が決まっている |
| N12 | AI の関与と投稿先の規約 | 既定のモード（通常／`--auto`）、作者が自分で書く話があるか、投稿先・応募先の AI 利用の規定を確かめたか（確かめる時期を決めただけでもよい） |

## 3. 手順

```text
1. 読み込み → 2. 充足判定 → 3. 診断（最初の 1 回） → 4. 壁打ち（未決がなくなるまで） → 5. 確定の提示 → 6. 書き出し
```

1. **読み込み**: `seed.md`、`direction.md`、`wide.md`、既存の `premises.md` と `backlog.md` を読む。
2. **充足判定**: 必須項目表を作り、確定・未決を判定する。
3. **診断**: 最初の 1 回だけ、選んだ方向性を小説家の役で診断する。効いている点、危うい点、最初に決めるべきことを示す。
4. **壁打ち**: 未決の項目を、N1 → N3 → N5 → N7 → N2 → 残りの順で優先して聞く。前の項目が、後の項目の選択肢を決めるためである。
   - 各問に選択肢を 2〜4 個付け、推奨案を先頭に `(Recommended)` 付きで置く。調査に基づく選択肢には、説明に出典を添える（例: 「類似作品 X・Y が採用」）。
   - 回答から新しい論点が出たら、該当する項目を「未決」に戻すか、項目を足す。
   - **ラウンドを終えるたびに `premises.md` を更新する**（充足状況表と質疑記録）。中断しても再開できるようにするためである。
   - 質疑記録は `#### Q<n>（ラウンド n）— <項目 ID>` の形で書く。
   - 方向性が大きく変わった場合（ジャンルや主人公の変更など）は、`novelkit-research-wide` での再調査を提案する。
   - 作者が「この項目は後で決める」と明示した場合に限り、未決のまま進めてよい。その場合は `[NEEDS CLARIFICATION: …]` を付けて残し、完了報告に挙げる。
5. **確定の提示**: 全項目の確定内容を表で示し、「この前提で進める / 修正する」を確かめる。
6. **書き出し**: `premises.md` を最終版にし、採らなかった案を `backlog.md` に足す。

### 自動モード

- 未決の項目は、`seed.md`・`direction.md`・`wide.md` から推奨案を作って採用し、「確定」にする。1 問ずつ深掘りする手順は、自動モードでは 1 ラウンドにまとめてよい（Q-ID は項目ごとに振る）。
- 質疑記録は `#### Q<n>（ラウンド 1, auto）— <項目 ID>` とし、回答の頭に `(auto: 仮定)` を付けて根拠を書く。
- N5（主人公のアーク）、N7（結末）、N2（読者）は、見直しの優先度を「高」にして `docs/auto-decisions.md` に記録する。
- N12 は「既定のモード: auto（AI が本文まで書く）」とし、投稿先の規約は `novelkit-publish` で確かめると書く。

## 4. 出力

- `docs/concept/premises.md`（様式: [templates/premises.md](./templates/premises.md)）
- `docs/concept/backlog.md`（様式: [templates/backlog.md](./templates/backlog.md)。既存の候補は消さず、状態だけを変える）

終わったら `W4` のチェックポイントを記録する。

## 5. 完了報告

- N1〜N12 の確定内容の要約（未決のまま残した項目があれば、その一覧）
- ネタ帳に足した件数
- 次の案内: `novelkit-research-deep`（W5）。考証の要らない題材なら、W5 は短くてよい
