# novelkit-analyze スキル（C3: 矛盾検出 ×3）

書く前に直す方が、書いた後に直すより安い。本文を書く前に、シーン台帳の段階で矛盾を取り除く。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 対象と入力

- `chapters/<章>/scenes.md`（対象）
- `chapters/<章>/spec.md`、`.novelkit/memory/constitution.md`
- `canon/`（timeline.md、人物、glossary.md、rules.md）
- `docs/plot/synopsis.md`（1 文・5 文・1 ページのあらすじ）、`structure.md`、`promises.md`、`threads.md`
- `docs/research/wide.md`（類似作品。とくに「重なりが大きい作品」）
- 前の章の `scenes.md`・`state.md`（終わりの状態）と、次の章の `spec.md`（前提）
- `docs/research/anachronism.md`

`--round` の指定がなければ、`novelkit.py state --chapter <章>` の `NEXT_STEP`（C3-1〜C3-3）に対応する回を行う。

## 2. 重大度

| 重大度 | 基準 |
|---|---|
| CRITICAL | 文体の決まりの MUST に反する。必須イベント（EV）を担う話がない。正典の優先順位の上位と矛盾する（年齢・日付）。伏せる名前を、開示の前の話で明かす設計になっている |
| HIGH | 全体構成（ビート・目的の層）と乖離している。synopsis の結末の要素が台帳に落ちている。特定の類似作品と展開の組み合わせが重なる。知識状態の矛盾（視点人物が知り得ないことを知っている）。前の章の終わりの状態と接続しない。伏線を回収する話が、張る話より前にある |
| MEDIUM | 呼称・用語の揺れ。価値の変化が単調（同じ向きが 3 話以上続く）。Disaster が同じ型ばかり。引きが弱い・ない。時代錯誤。筋の入れ子の交差 |
| LOW | 表記の細部、欄の書き漏れ（必須以外） |

## 3. 手順（各回に共通）

1. `check.py --only structure,canon,promises,threads` を実行し、結果を材料にする。
2. §4 のその回の観点で、シーン台帳を読む。
3. 検出結果を表にまとめる（様式は §5）。
4. 直し方を決める。
   - 直し方が 1 つに決まるものは直す。
   - 判断が要るものは推奨案（`**Recommended:**`）を添えて質問する（通常モード）。自動モードでは推奨案を当て、`chapters/<章>/auto-decisions.md` に記録する。
5. 修正を当て、`check.py` を再実行して ERROR が 0 件であることを確かめる。
6. 検出結果と修正を `chapters/<章>/reviews/analyze-<回>-YYYY-MM-DD.md` に保存する（再実行しても前の結果を上書きしない）。
7. チェックポイントを記録する（C3-1、C3-2、C3-3。指摘が 0 件で変更がなくても記録する）。

章仕様の変更が必要になった場合は、`spec.md` を直し、`## Clarifications` に `### Session YYYY-MM-DD (analyze)` として記録する。**文体の決まりの改訂が必要になった場合は、直さずに報告する**（`novelkit-constitution` の改訂を経る）。

## 4. 各回の観点

### C3-1（重大・カバレッジ）

- 文体の決まりの MUST 条項（語り・構成の型・禁止事項）に、台帳が反していないか
- EV・IR・CH のすべてが、どれかの話に割り当てられているか
- 章の役割（全体構成での位置）と、台帳の山場・結末が一致しているか
- **`synopsis.md`・`structure.md` との照合**: あらすじの 5 文と 1 ページのあらすじに書いた出来事・結末の要素が、台帳のどれかの話に割り当てられているか。台帳にない要素は、落としたのか、意図して外したのかを確かめる（落としたなら台帳に足す。外したなら synopsis に理由を書く）
- **類似作品との展開の重なり**（書く前の早い確認）: 台帳の展開の組み合わせが、`wide.md` の「重なりが大きい作品」のどれかと、ありふれていない形で複数重なっていないか。重なるなら、C7（類似性軸）を待たずに、台帳の段階で差をつける
- 話数と字数の合計が、SC を満たすか
- 「変わること」が空、または前後の話と同じ話がないか

### C3-2（詳細・整合）

- **呼称と用語**: 登場・シーンの記述の呼び方が、口調の早見表と `glossary.md` に一致するか
- **時系列**: 作中年・季節・柱の時間帯が、前後の話と年表に一致するか。移動にかかる日数（`place/`）と矛盾しないか
- **年齢**: `年齢` 欄と、作中年 − 生年（`check.py` の結果）
- **知識状態**: 各話の視点人物が、その時点で知っていることだけで動いているか。読者が知っていることと、人物が知っていることの差（劇的アイロニー）が、IR の設計どおりか
- **伏線と筋**: 張る → 進展 → 回収の順か。筋の入れ子が交差していないか（意図した交差は `threads.md` の「意図」にあるか）
- **接続**: 最初の話の前提が、前の章の終わりの状態と一致するか。最後の話の引きが、次の章の前提につながるか
- **時代錯誤**: `anachronism.md` の語や物が、台帳に出ていないか

### C3-3（最終確認）

- CRITICAL・HIGH・MEDIUM が 0 件であること
- EV のカバレッジが 100% であること
- `check.py` の ERROR が 0 件であること

満たさなければ直してから記録する。LOW は、直さずに残してよい（一覧を報告する）。

**短編（章が 1 つで、話が 5 本以下）の場合**: 1 回目と 2 回目の観点をまとめて 1 回で見てよい（C3-1 の記録に両方の観点を書き、C3-2 は「C3-1 で併せて確かめた」と記録する）。3 回目の最終確認は省かない。

## 5. 検出結果の様式

```markdown
# 矛盾検出 <回> — <章>（YYYY-MM-DD）

| # | 重大度 | 観点 | 対象（話番号・欄） | 内容 | 直し方 | 状態 |
|---|---|---|---|---|---|---|
| 1 | CRITICAL | カバレッジ | EV-004 | 担う話がない | 4-09 に割り当てる | 修正済み |

- check.py: ERROR 0 / WARN 2（内容）
- 直さずに残したもの:
```

## 6. 完了報告

- 回ごとの検出件数（重大度別）と、直したもの
- 質問して決めたこと（自動モードでは採用した推奨案）
- 3 回目の時点での EV カバレッジと check.py の結果
- 次の案内: `novelkit-write <章>`（C4〜）
