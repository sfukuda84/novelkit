# novelkit-plot スキル（W8: プロットの詳細化 → 章仕様）

プロット概要を、章ごとの「何を読者に体験させるか」の仕様にする。**章仕様は WHAT（何が起き、読者が何を得るか）と WHY（なぜこの章が要るか）を書き、HOW（何話で、どの場面で）は書かない。** 話への割り当ては、章の工程のアウトライン（C2）で決める。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 入力

- `docs/plot/synopsis.md`、`docs/plot/structure.md`、`docs/plot/promises.md`
- `canon/`（核の人物・世界の規則）
- `docs/concept/premises.md`（N3 の約束事と必須シーン、N9 の分量）
- `.novelkit/memory/constitution.md`（構成の型、話番号の規則）

## 2. モード判定

| 条件 | モード |
|---|---|
| `chapters/` に章がない | **新規**（全章を作る） |
| 引数で章が指定され、その章がある | **更新**（その章の仕様を直す） |
| 引数で新しい章の追加・分割・統合が指定された | **再編**（章の一覧を変える） |

- 更新と再編では、C4（執筆）以降に進んだ章の `spec.md` を書き換えない。影響だけを報告し、`novelkit-converge` の逆流で扱う。
- 章の番号（ディレクトリ名の `NN`）は、一度振ったら変えない。後から足す章は、既存の最大値の次の番号にする。掲載順は `structure.md` の章の一覧で表す。

## 3. 手順

### ステップ 1: 章の分割案

1. `structure.md` のビートと N9 の章の数から、章の分割案を作る。1 章 ＝「主人公の状況が 1 段変わる」単位にする。
2. 分割案を表で示す。列は次のとおり。

   | 章 | ディレクトリ | 題 | 位置（ビート） | 主人公の状況の変化 | 主な出来事 | 分量の目安 |
   |---|---|---|---|---|---|---|

   - ディレクトリ名は `NN-<slug>`（例: `01-homecoming`）。`NN` は 2 桁の章番号、slug は英小文字のケバブケース 2〜4 語。
3. 配分を点検する。
   - 前半に厚く後半が薄い、または山場が 1 つの章に集中しているなら、再配分を提案する。
   - 目的が早い章で達成され、その後に牽引力がないなら、次の目的を示す。
4. **通常モード**: 分割案の承認を得る。合意するまで書き出さない。**自動モード**: 推奨案のまま進む。

### ステップ 2: 章仕様の作成

承認した章ごとに `chapters/<NN>-<slug>/spec.md` を作る（様式: [templates/spec.md](./templates/spec.md)）。

| 節 | 書くこと | ID |
|---|---|---|
| 章の役割 | 全体構成での位置（ビート）と、この章がなければ何が成り立たないか | — |
| 読者体験 | 優先順（P1、P2…）に並べた読者体験。受入基準は「**読み終えた読者の状態**」（何を知っている、何を疑っている、何を期待している、何を感じている）で書く | `RX-NNN` |
| 必須イベント | この章で必ず起きること。ジャンルの必須シーン（N3）は、どの章の EV にするかを必ず決める | `EV-NNN` |
| 情報開示 | 読者に明かすこと・伏せること・読者だけが知ること（劇的アイロニー）と、その時点 | `IR-NNN` |
| 人物の変化 | 人物ごとの変化（Lie がどこまで揺らぐか、関係がどう変わるか） | `CH-NNN` |
| 成功基準 | 話数、字数、各話の引き、正典との一致など、確かめられる基準 | `SC-NNN` |
| 前提 | この章が前提にする正典と、前の章の結果 | — |
| スコープ外 | この章でやらないこと（次の章に回すこと） | — |
| Clarifications | 詰めの記録 | — |

- ID は章ごとに 001 から振る。シーン台帳（C2）がこの ID を参照し、`check.py` がカバレッジを検証する。
- 数値（話数、字数）は N9 と文体の決まりから決める。話の内訳（どの話で何を書くか）は書かない。
- 決まっていないことは `[NEEDS CLARIFICATION: …]` と書き、推測で埋めない。

### ステップ 3: 伏線と約束の台帳

`docs/plot/promises.md` を、章の単位で埋める（様式: [templates/promises.md](./templates/promises.md)）。

- 種類は、次の 3 つ。
  - `伏線`: 後で意味が分かる手がかり
  - `約束`: 読者に期待させること
  - `小道具`: チェーホフの銃。出したなら使う
- 各行に次を書く。
  - 「張る」「進展」「回収予定」の章
  - 真相（読者にまだ見せない答え）
- この時点では、章番号（例: `第3章`）で書く。C2 で話番号（例: `3-05`）に置き換える。
- 章仕様の IR と対応させる。伏せる情報は、どこで回収するかを必ず決める。

### ステップ 4: 筋の入れ子の台帳

`docs/plot/threads.md` を作る（様式: [templates/threads.md](./templates/threads.md)）。物語の筋を MICE の 4 種類に分け、開く章と閉じる章を書く。

| 種類 | 開くとき | 閉じるとき |
|---|---|---|
| M（舞台） | 新しい場所に入る | その場所を出る |
| I（謎） | 問いが立つ | 答えが出る |
| C（人物） | 人物が自分に不満を持つ | 人物が変わる、または変わらないと決める |
| E（出来事） | 世界の秩序が乱れる | 新しい秩序ができる |

**後に開いた筋を先に閉じる**（入れ子にする）。交差する筋は、意図があるなら「意図」の列に書く。

### ステップ 5: 詰め 1 回目（核）

全章の仕様を通して読み、次の論点の曖昧さと決定漏れを探す。

- 各章の主人公の目的と障害
- 転換点（ビート）がどの章のどの EV に当たるか
- 山場の位置と、そこで主人公が得るもの・失うもの
- 各章の読者体験が、前の章と重複していないか
- ジャンルの必須シーンの割り当て

最重要の論点を 3〜5 問、推奨案（`**Recommended:**`）と理由を添えて質問する。回答は該当する `spec.md` の `## Clarifications` > `### Session YYYY-MM-DD (Round 1)` に記録し、本文（RX・EV・CH など）に反映する。

### ステップ 6: 詰め 2 回目（整合）

1 回目の決定を前提に、一段深い整合を確かめる。

- **時系列**: 章をまたぐ時間の経過、季節、年齢（`canon/timeline.md` があれば照合する）
- **知識状態**: 各章の終わりで、主人公・主要人物・読者がそれぞれ何を知っているか。視点人物が知り得ない情報が、その章の IR で明かされていないか
- **伏線**: 張ったまま回収されない伏線、回収だけあって張っていない伏線
- **筋の入れ子**: 交差、閉じ忘れ
- **章の接続**: 前の章の終わりの状態と、次の章の前提が一致しているか

残る論点を推奨案とともに質問し、`### Session YYYY-MM-DD (Round 2)` に記録して反映する。

### 自動モード

- ステップ 1 の承認と、ステップ 5・6 の質問は、推奨案を回答として採用する。
- 見出しを `### Session YYYY-MM-DD (Round 1, auto)` とし、回答の頭に `(auto: 仮定)` を付ける（`novelkit-status` §4「自動モードの記録」）。
- 章の分割、山場の位置、主要人物の生死に関わる決定は、`docs/auto-decisions.md` に見直しの優先度「高」で記録する。

### ステップ 7: 一覧の更新と検証

1. `structure.md` の「章の一覧」を更新する。
2. `python3 <skills>/novelkit-check/scripts/check.py --only structure,promises,threads` を実行し、ERROR が 0 件になるまで直す。この時点ではシーン台帳がないので、「scenes.md がまだない」の INFO は正常である。

## 4. 出力

- `chapters/<NN>-<slug>/spec.md`（章ごと）
- `docs/plot/promises.md`、`docs/plot/threads.md`
- `docs/plot/structure.md`（章の一覧）

W8 として実行したときは、`W8` のチェックポイントを記録する。後から章を直したときは、通常のコミット（`docs(<章>): 章仕様を更新`）にする。

## 5. 完了報告

- 章の一覧（章・題・位置・一言）
- 詰め 2 回で決めた重要な事項
- 伏線・約束の件数、筋の件数と入れ子の検証結果
- 残した `[NEEDS CLARIFICATION]`
- 次の案内: `novelkit-canon`（W9）
