# novelkit-draft スキル（C4: 執筆）

シーン台帳の 1 行を、1 話の本文にする。**台帳にないことを足さない。台帳と違う方が良いと思ったら、書いたうえで報告する**（逆流の材料にする。C9）。

進捗の記録、モード、文脈パック、AI の関与の記録は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 対象

- 引数の話番号・範囲。なければ、台帳の未完了（`- [ ]`）の話を上から順にすべて書く。
- `[P]` の話は、前後に依存しないので、順序を入れ替えてよい。それ以外は台帳の順に書く。前の話の終了時点の状態を、次の話が使うためである。
- 章の C3-3 が未完了なら、先に `novelkit-analyze` を勧める（ユーザーが了承すれば進めてよい）。

## 2. 1 話の手順

### ステップ 1: 文脈パックを組み立てて読む

```bash
python3 <skills>/novelkit-status/scripts/novelkit.py context <話番号> --out chapters/<章>/context/<話番号>.md
```

- 出力したファイルを最初から最後まで読む。**「この話で伏せるもの」は必ず守る。**
- 正典が拾われていない人物・場所が台帳のシーンに出てくるなら、台帳の「登場」に書き足して組み直す。
- 考証が要る場面（戦・医療・道具・時代の暮らし）で `docs/research/deep/` に資料がなければ、`novelkit-research-deep` で調べてから書く（通常モードでは、調べるかどうかを確かめる）。

### ステップ 2: 書く

- **書く前に、字数を箱に割り振る。** 台帳の「目安」を箱の数で割り、箱ごとの字数の見当を付けてから書く（例: 目安 3,300 字・箱 3 つなら、1 箱 1,100 字前後）。1 箱書くごとに `check.py --episode <話番号> --only length` で測り、ずれを次の箱で直す。書き手の字数の見積もりは、実測より少なく出やすい。
- 足りないときは、言葉を足さず、**場面を足す**（台帳の箱の中で描いていない動き・音・やり取り）。多すぎるときは、場面を削る。

- **文体の決まり**（語り・表記・禁止事項・声のサンプル）に従う。声のサンプルの文の長さ、台詞と地の文の配分、改行の癖に合わせる。
- **台帳の要素をすべて本文にする。**
  - 箱（ハコ書き）の順に、柱の場所・時間帯で場面を立てる。
  - シーン（Goal → Conflict → Disaster）と、シークエル（Reaction → Dilemma → Decision）を場面として書く。地の文の要約で済ませない（文体の決まり K-4-4）。
  - 「変わること」が起きる瞬間を、場面の中で見せる。
  - 伏線を張る話では、読者が後で気づける程度に、さりげなく置く。
  - 最後の段落に「引き」を置く。
- **正典に合わせる。** 人物の口調（早見表）、呼び方、外見、年齢、場所の特徴、世界の規則、用語の正表記。
- **視点を守る。** 視点人物が知り得ないこと、見ていないことを地の文に書かない（一人称・三人称一元の場合）。
- **字数**は台帳の目安の ±20% に収める。
- 本文ファイルを、台帳の「出力」のパスに、[templates/draft.md](./templates/draft.md) の形で書く。

  | 欄 | 通常モード | 自動モード |
  |---|---|---|
  | `status` | `下書き` | `確定` |
  | `ai` | `AI本文` | `AI本文` |

  通常モードでは、作者が推敲して確定したら、作者か AI が `status: 確定`、`ai: AI下書き→作者推敲` に書き換える。

### ステップ 3: 検査する

```bash
python3 <skills>/novelkit-check/scripts/check.py --episode <話番号>
```

ERROR（伏せる名前の早漏れ、年齢の不一致など）は直す。WARN（字数、文章の指標、表記の揺れ）は直すか、意図どおりなら残す。

### ステップ 4: 記録を更新する

1. **状態**（`chapters/<章>/state.md`）に、`## <話番号> <題>` の節を足す（様式: [templates/state.md](./templates/state.md)）。
   - 対象: 話の終了時点の居場所、負傷・体調、所持品・服装、時刻・天候・季節、関係の変化、誰が何を知ったか（読者を含む）
   - 前の話から変わったものだけでなく、次の話が引き継ぐものはすべて書く。
2. **要約**（`chapters/<章>/summaries.md`）に、`## <話番号> <題>` の節を足す（約 200 字）。
   - 起きたことと変わったことだけを書く。後の話の文脈に入り、AI はそこに書かれたことを重要なものとして扱う。重要でない細部は書かない。
3. **伏線台帳**（`docs/plot/promises.md`）: この話で張った・進めた・回収したものの状態を更新する。
4. **シーン台帳**: その話を `- [x]` にする（本文が `下書き` でも `[x]` にする。確定かどうかは本文の `status` で表す）。
5. **台帳と違うものを書いたとき**: 違い（何を、なぜ）を `chapters/<章>/reviews/draft-notes.md` に書く。C9（収束と逆流）の材料になる。
6. 本文と、1〜5 の記録の更新を、**1 つの**通常のコミットにまとめる（trailer なし。例: `draft(<章>): <話番号> を執筆`）。

## 3. 作者が書く話（`[人]`）

`[人]` は通常モードで付ける。自動モードでも、台帳に残っている `[人]` の話は書かない（`novelkit-status` §4）。

1. 文脈パックを組み立てて保存し、パスを作者に伝える。
2. 本文は書かない。台帳も `[x]` にしない。
3. 作者が書き終えたと伝えたら、ステップ 3 とステップ 4 を行う。本文の `ai` は `作者執筆＋AI補助`（AI が文脈パックや検査を使った場合）にする。
4. 待っている間は、依存しない後続の話（`[P]`、または作者の話の結果に依存しない話）を書いてよい。依存する話は保留にし、完了報告に挙げる。

## 4. 章の全話を書き終えたら

1. `check.py --chapter <章>` を実行し、ERROR が 0 件であることを確かめる。
2. `C4` のチェックポイントを `--chapter <章>` で記録する。未完了の `[人]` の話が残っていてもよい（残りを完了報告に挙げる）。

## 5. 完了報告

- 書いた話（話番号・題・字数・status）
- 作者が書く話の文脈パックのパスと、保留にした話
- check.py の結果
- 台帳と違う書き方をした箇所（draft-notes.md）
- 次の案内: `novelkit-review <章> story`（C5）。レビューは物語 → 整合 → 類似性 → 文章の 4 軸
