# novelkit-outline スキル（C2: 1 話ごとのアウトライン → シーン台帳）

章仕様の「何を体験させるか」を、話ごとの「どの場面で、何が変わるか」にする。シーン台帳は、**設計（この工程）・執筆の指示（C4）・書いた後の診断（C5〜C10）の 3 つに同じ形で使う**。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 入力

- `chapters/<章>/spec.md`（RX・EV・IR・CH・SC、Clarifications）
- 前の章の `scenes.md`・`state.md`・`summaries.md`（前の章の終わりの状態）
  - 前の章をまだ書いていない（`state.md` がない）場合は、前の章の `scenes.md` の最後の話と、`spec.md` の「人物の変化」を、終わりの状態の予定として前提にする。前の章を書いた後の C9（収束と逆流）で差が出たら、この章の `spec.md` に「上流からの変更」として届く
- `docs/plot/structure.md`、`promises.md`、`threads.md`
- `canon/`（README の口調の早見表、timeline.md、人物の生年）
- `.novelkit/memory/constitution.md`（1 章の型、話番号の規則、1 話の字数、作者が自分で書く話の基準）

`spec.md` がなければ `novelkit-plot` を案内する。

## 2. シーン台帳の形式

様式は [templates/scenes.md](./templates/scenes.md)。**1 行目の形は `check.py` と `novelkit.py` が読むので厳守する。**

```markdown
- [ ] T004 [4-03] [EV-003] [IR-002] 当番
  - 視点: ヴォルフ（一人称）
  - 柱: 冬営地・朝 → 夕
  - 作中年: 9
  - 年齢: ヴォルフ 9, サヤ 8
  - 目安: 5,000 字
  - 登場: ヴォルフ、サヤ、団員（言及のみ: カサル）
  - 変わること: 二十三人に当番と規則が要ると分かる
  - 価値: 無秩序 → 秩序（－→＋）
  - シーン: Goal 狩の分配を決める → Conflict 年長組が従わない → Disaster Yes, but（決まるが、一人が抜ける）
  - シークエル: Reaction 苛立ち → Dilemma 規則で縛るか → Decision 名簿を作る
  - 伏線: 張る F-012
  - 約束: 進展 PR-003
  - 筋: 開く TH-004
  - 引き: 名簿に空欄が一つ残る
  - 箱1: ○食卓・朝／分配の揉め事が持ち込まれる
  - 箱2: ○狩場・昼／年長組が指示を無視する
  - 箱3: ○天幕・夕／名簿を書き始める。空欄が残る
  - 出力: draft/04/4-03-当番.md
```

| 部分 | 規則 |
|---|---|
| `- [ ]` | 未執筆。本文を書き終えたら `- [x]`（C4 が更新する。下書きでも `[x]`。確定かどうかは本文の `status` で表す） |
| `T004` | タスク ID。章の中で一意。T001 から順に振る |
| `[P]` | 任意。前後の本文に依存せず、並行して書ける話（幕間など） |
| `[人]` | 任意。作者が自分で書く話（通常モードだけ。§3 ステップ 4） |
| `★` | 任意。山場 |
| `[4-03]` | 話番号（文体の決まりの規則。本章 `<章>-<番号>`、プロローグ `<章>-P`、幕間 `<章>-i<n>`、エピローグ `<章>-E`） |
| `[EV-003]` … | この話が担う章仕様の ID（1 つ以上） |
| 末尾 | 話の題 |

子の行（`  - キー: 値`）のうち、**視点・変わること・引き は必須**。そのほかも、分かるものはすべて書く。とくに次の 2 つは、`check.py` が年齢の検証に使う。

- `作中年`: 年表の基準での年
- `年齢`: 「名前 数字」をカンマ区切りで並べる

`箱N` はハコ書きの箱である。1 箱に 1 シーンを入れ、柱（○場所・時間帯）から書く。

## 3. 手順

### ステップ 1: 話の枠を決める

1. `spec.md` の SC（話数・字数）と、文体の決まりの 1 章の型から、話の枠を並べる。例: プロローグ、本章 16 話、幕間 4 話、エピローグ。
2. 章の中の山場（★）と、章の型のビート（起承転結など）の位置を決める。

### ステップ 2: 必須イベントと情報開示を話に割り当てる

1. 全 EV を、どれかの話に割り当てる。1 つの EV を複数の話に分けてよい。割り当てのない EV は作らない（`check.py` が ERROR にする）。
2. IR は、「明かす話」「伏せ続ける話」を決める。
   - この章で明かす名前は、`canon/` の該当項目の `reveal_from` を、章の指定（`第N章`）から明かす話の話番号（例: `3-05`）に書き換える。
   - 後の章で明かす名前の `reveal_from` は、章の指定（`第N章`）のままでよい。その章より前の話では、すべて伏せる扱いになる。
3. CH（人物の変化）は、変化が見える話に割り当てる。

### ステップ 3: 1 話ずつ組む

各話について、次の順で決める。

1. **変わること**: この話の前後で、何が変わるか（状況・関係・知識・感情）。**何も変わらない話は作らない。** 変わらないなら、前後の話と統合する。
2. **価値の変化**: 変わることを、価値の言葉にする（例: 安全 → 危険、孤立 → 信頼）。向き（＋→－ / －→＋）を書く。同じ向きが 3 話以上続くなら、単調でないか確かめる。
3. **シーンとシークエル**:
   - シーン（Goal → Conflict → Disaster）。Disaster は「No（失敗する）」「Yes, but（得るが代償がある）」「No, and furthermore（失敗し、さらに悪化する）」のどれかにする。
   - シークエル（Reaction → Dilemma → Decision）。その Decision が、次の話の Goal になるようにつなぐ。
4. **ハコ書き**: 話の中を 2〜5 個の箱に分け、箱ごとに柱と中身を 1 行で書く。
5. **引き**: 話の最後の一文・一場面で、次の話を読みたくさせるもの（小さな謎、感情の揺れ、予告）。
6. **連続性の欄**:
   - 視点、柱、作中年、年齢、登場。登場は、言及だけの人物も「言及のみ」として書く。文脈パックが正典を拾うためである。
   - 伏線（張る・進展・回収）、約束、筋（開く・閉じる）。ID は `promises.md`・`threads.md` のものを使う。
7. **目安**: 字数。文体の決まりの 1 話の字数に合わせる。山場は多めにしてよい。
8. **出力**: 本文のパス。`draft/<章番号 2 桁>/<話番号>-<題>.md`。

Web 連載（premises.md の N2）の場合は、次も点検する。

- 1 話目で、物語の向かう先と主人公の目的が見えるか。
- 1 話目で、設定を詰め込みすぎていないか。
- すべての話に引きがあるか。

### ステップ 4: 作者が書く話（通常モード）

文体の決まりの K-7-2（作者が自分で書く話の基準）に当たる話に `[人]` を付ける。基準がなければ、★ の話に `[人]` を付けるかを質問する（推奨案は「付けない。AI が下書きし、作者が推敲する」）。自動モードでは `[人]` を付けない。

### ステップ 5: 台帳を話番号に落とす

- `promises.md` の「張る」「進展」「回収予定」を、章番号から話番号に置き換える。
- `threads.md` の「開く」「閉じる」を、話番号に置き換える。
- 状態を更新する（例: 張る話を決めたものは、状態を「未着手」のままにし、C4 で張ったら「張った」にする）。

### ステップ 6: 提示と承認

話の一覧（話番号・題・変わること・価値・引き・★・[人]）を表で示す。

- **通常モード**: 承認を得る。修正があれば直して再提示する。合意するまで書き出さない。判断が要る論点は、推奨案つきで質問する。例: 話の統合・分割、山場の位置、視点の割り当て。
- **自動モード**: 推奨案のまま書き出し、話の配分と山場の位置を `chapters/<章>/auto-decisions.md` に記録する。

### ステップ 7: 書き出しと検証

1. `scenes.md` を書き、`promises.md`・`threads.md`・`canon/` の `reveal_from` を更新する。
2. `check.py --only structure,canon,promises,threads` を実行し、ERROR を 0 件にする。
3. 最初の話の文脈パックを試しに組み立て（`novelkit.py context <最初の話番号>`）、正典が拾われているかを確かめる。拾われない項目があれば、「登場」に名前を書き足す。

## 4. 出力

- `chapters/<章>/scenes.md`
- `docs/plot/promises.md`、`docs/plot/threads.md`、`canon/` の `reveal_from`（更新）

終わったら `C2` のチェックポイントを `--chapter <章>` で記録する。

## 5. 完了報告

- 話の数（本章・プロローグ・幕間・エピローグ）と、山場・作者が書く話
- EV・IR のカバレッジ（check.py の結果）
- 話番号に落とした伏線・筋の件数
- 次の案内: `novelkit-analyze`（C3-1）
