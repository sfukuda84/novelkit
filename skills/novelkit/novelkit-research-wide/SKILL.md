# novelkit-research-wide スキル（W2: 広域調査）

方向性を決める前に、題材の「地図」を作る。ここで集めたものは **方向性の案（W3）と壁打ち（W4）の材料**であり、作品の決定ではない。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 0. 大原則

- **出典のない事実を書かない。** 作品の情報、史実、統計には、出典 URL と参照日を付ける。
- **AI が挙げた作品名は、1 件ずつ実在を確かめる。** 実在しない作品や、作者・年・内容の取り違えが起きやすい。検索で公式ページ、出版社・配給元のページ、データベース（書誌、作品データベース、百科事典）のどれかに当たれたものだけを載せる。当たれなかったものは「未確認」として別表に分け、根拠にしない。
- **Wikipedia は入口として使う。** 引用するときは版を記録し、W5 で一次資料に当たる対象にする。版は、版 ID（oldid）が取れなければ最終更新日時でよい（MediaWiki の API `https://ja.wikipedia.org/w/api.php?action=query&prop=revisions&titles=<題>&format=json` で取れる）。
- **ページを開けない出典**: TV Tropes のように取得が拒否される（403）サイトは、検索結果の要約か、内容を写したミラー（Tropedia など）で確かめ、その旨を出典の欄に書く（例: 「検索結果の要約で確認」）。レビューサイト（読書メーター、Filmarks など）も同じ。**検索の要約モデルは固有名詞を取り違えることがある**ので、要約だけで確かめた固有名詞は、別の出典でもう一度確かめる。
- **調べたが見つからなかったこと**は、それ自体を記録する（「〜を主人公にした作品は、検索語 ○○・○○ では見つからなかった（参照日）」）。見つからないことが「空いている席」の根拠になる。ただし、見つからないことは存在しないことの証明ではない。
- **既存の記述は消さない。** 再実行したときは、日付つきの新しい節を足す。

### 始める前に（検索の予算）

`python3 <skills>/novelkit-status/scripts/novelkit.py budget --step W2` を実行する（単独で題目を 1〜2 個だけ調べるときは `--need <見積もり>`）。STOP なら始めずに止まり、新しいセッションで実行するよう案内する（`novelkit-status` §3「セッションの区切り」）。

## 1. 入力

- `docs/concept/seed.md`（原文、ログライン、調査の論点、選択）
- 引数の追加の観点
- 既存の `docs/research/wide.md`（あれば、重複を避ける）

`seed.md` がなければ `novelkit-seed` を案内する。

## 2. 手順

### ステップ 1: 調査計画

`seed.md` の「調査の論点」と選んだログラインから、次の 4 つの調査の問いを作り、`wide.md` の冒頭に書く。

| 系統 | 調べること |
|---|---|
| A. 類似作品 | 同じ設定・同じ構図・同じ感情の核を持つ作品。媒体を問わない |
| B. 現実の事例・歴史 | 題材の元になりうる出来事、人物の類型、職業・制度・技術の実態 |
| C. トロープ | この題材で定番の型（TV Tropes などのトロープ名で特定する） |
| D. 読者 | 想定読者が、この系統の作品のどこを評価し、どこに不満を持っているか |

### ステップ 2: 類似作品（A）

- **件数の目安**: 小説 5〜8 件、漫画・映像・ゲームから 3〜6 件。「誰もが知る原型」（下）はこの件数に含めない。漫画と映画の両方がある作品は、1 件として数え、媒体の欄に両方を書く。Web 連載を想定しているなら、投稿サイトの同系統の人気作も入れる。
- **比較に向く作品を優先する。** 最近の作品と、現役の作家の作品を優先する。超ベストセラーや映像化された有名作は、「誰もが知る原型」として別枠に置く。
- 各作品について、次を記録する。
  - 題名、作者・制作、媒体、年
  - 出典と参照日
  - 設定と構図の要約（1〜2 文）
  - 受けた点、読者の不満（レビュー・比較記事から。出典つき）
  - 使っているトロープと、その扱い方
  - 本作との重なり（設定／構図／感情の核／結末）
- **重なりが大きい作品には印を付ける。** 記録した 4 つの観点（設定・構図・感情の核・結末）のうち 2 つ以上が重なる作品を「重なりが大きい」とする。部分的な重なり（半分だけ同じ、など）は 0.5 と数える。重なりが大きい作品は、W3 で「差のつけ方」を必ず検討し、C3・C7 で展開の重なりを確かめる対象にする。
- **誰もが知る原型**（超ベストセラー・古典・映像化された有名作）は、テンプレートの「A''. 原型」の表に分けて置く。比較の基準として使い、「重なりが大きい」の判定には含めない。

### ステップ 3: 現実の事例・歴史（B）

- 題材に関わる出来事・制度・職業・技術・地域・時代を調べる。
- 出典は、辞典・公的機関・研究機関・報道機関・専門書の紹介を優先する。個人ブログは補助にとどめる。
- 実在の人物・団体・事件が関わる場合は、その旨を明記する。W5 で、モデルにしてよいかを点検する対象にする。

### ステップ 4: トロープ（C）

- この題材で使われやすいトロープを 5〜15 個特定する。各トロープに、次を書く。
  - 名前（原語名と、日本語での通称）
  - 典型的な使われ方
  - 類似作品での扱い方。次の 6 種類から選ぶ。

    | 扱い方 | 意味 |
    |---|---|
    | そのまま | 型どおりに使う |
    | 逆転 | 要素を入れ替える |
    | 外す | 期待させておいて、違う結果にする |
    | 使わない | 型が来そうな場面で使わない |
    | 言及 | 作中で型だと指摘する |
    | 脱構築 | 型を現実的に突き詰め、その帰結を描く |

- 「外す」が見かけだけになりやすい点に注意する。単に逆にしただけのものは、外したことにならない。

### ステップ 5: 読者（D）

- 想定読者が集まる場所（投稿サイトのランキングとレビュー、書評サイト、比較記事など）から、評価と不満の傾向をまとめる。出典つき。

### ステップ 6: KJ 法でまとめる

1. A〜D で集めた事実を、1 件 1 行のラベルにする。
2. 似たものを集めてグループにし、各グループに内容を一言で表す見出し（表札）を付ける。
3. 表札の関係（対立・因果・包含）を短く書く。
4. 最後に、「**この題材で読者が求めているもの**」と「**まだ空いている席**」を、それぞれ 3 行以内で書く。空いている席とは、類似作品が扱っていない組み合わせや、読者の不満が解消されていない点である。

### ステップ 7: 種への影響

調査で、種（`seed.md`）のログラインや前提を揺るがす発見（例: 種の設定が時代考証と合わない、同じ設定の有名作がある）があれば、`wide.md` の「種への影響」の節に書く。W3 は、この節を最初に読んで案を作る。

### ステップ 8: 提示

`wide.md` を書き、要点（空いている席と、重なりが大きい作品）をユーザーに示す。

- **通常モード**: 追加で調べたい観点を聞く（「このままで W3 へ」を推奨案にする）。追加があれば、ステップ 2〜6 を足してから終える。
- **自動モード**: 追加の調査はしない。重なりが大きい作品の一覧を `docs/auto-decisions.md` に記録する（見直しの優先度: 中）。サブエージェントとして呼ばれたときは、記録すべき判断を最終回答で返し、記録は親が行う（`novelkit-status` §3「サブエージェントに任せるとき」）。

## 3. 出力

`docs/research/wide.md`（様式: [templates/wide.md](./templates/wide.md)）

Web を調べられない環境では、推測で埋めない。調べるべき項目と理由を `wide.md` に「未調査」として書き、ユーザーに伝える。自動モードでは、その項目の見直しの優先度を「高」にする。

終わったら `W2` のチェックポイントを記録する。

## 4. 完了報告

- 類似作品の件数（確認済み / 未確認）と、重なりが大きい作品
- 主なトロープと、その扱われ方の傾向
- 読者が求めているもの、まだ空いている席
- 次の案内: `novelkit-direction`（W3）
