# novelkit-converge スキル（C9: 収束と逆流）

本文と設計のずれを、放置しない。どちらを正とするかを 1 件ずつ決め、**本文・台帳・章仕様・正典を同じ状態にしてから章を閉じる。**

進捗の記録、モード、作者の本文を守る規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 入力

- `chapters/<章>/` の本文、`scenes.md`、`spec.md`、`state.md`、`summaries.md`
- `chapters/<章>/reviews/`（C5〜C8 のレビュー、`draft-notes.md` の逆流の候補）
- `canon/`、`docs/plot/promises.md`・`threads.md`
- 後続の章の `spec.md`・`scenes.md`（影響の調査に使う）

## 2. ずれの洗い出し

本文を、章仕様とシーン台帳と照合し、ずれを次の種類に分ける。

| 種類 | 意味 | 例 |
|---|---|---|
| `missing` | 設計にあるが、本文にない | 必須イベント、引き、張るはずの伏線 |
| `partial` | 本文にあるが、弱い・不完全 | 「変わること」が起きたが、読者に伝わらない |
| `contradicts` | 本文が設計や正典と矛盾する | 年齢、呼び方、居場所、知識状態 |
| `unrequested` | 設計にないものが本文にある | 新しい人物、新しい伏線、予定にない展開 |

`draft-notes.md` の記録と、レビューで「逆流の候補」とした指摘も、この一覧に入れる。

## 3. どちらを正とするか

ずれを 1 件ずつ、次のどちらかに振り分ける。

| 振り分け | 条件 | 扱い |
|---|---|---|
| **収束**（本文を直す） | 設計が正しく、本文が書き漏らした・誤った | `scenes.md` の末尾に `## 収束（YYYY-MM-DD）` の節を作り、タスクを足す（§4）。本文を直す |
| **逆流**（設計を直す） | 本文の方が良い。書いて見つかった展開、人物の自然な反応など | 台帳・章仕様・正典を本文に合わせる（§5） |

- `contradicts` のうち、正典の優先順位の上位（年表・人物）と矛盾するものは、原則として**収束**にする。逆流にするには、作者の了承が要る（自動モードでは逆流にしてよいが、見直しの優先度を「高」にする）。
- `unrequested` は、物語に効いているなら逆流（台帳・正典に取り込む）、効いていないなら収束（本文から除く）にする。
- **通常モード**: 振り分けの一覧を示し、推奨案つきで承認を得る。
- **自動モード**: 推奨案で振り分け、`chapters/<章>/auto-decisions.md` に記録する。

## 4. 収束（本文を直す）

1. `scenes.md` の末尾に、次の形で収束タスクを足す。既存のタスクは書き換えない。

   ```markdown
   ## 収束（YYYY-MM-DD）

   - [ ] T031 [4-03] [EV-003] 収束: 当番の決定の場面が要約で畳まれている（partial）→ 場面にする
   ```

2. `novelkit-draft` のステップ 2〜4 の手順で本文を直し、タスクを `[x]` にする。
3. 本文が `status: 確定` の話、または `[人]` の話は、通常モードでは修正案を示して了承を得てから直す。

## 5. 逆流（設計を直す）

1. **シーン台帳**: 該当する話の欄（変わること、登場、伏線、引きなど）を本文に合わせる。行を書き換えたら、ブロックの末尾に `  - 逆流: YYYY-MM-DD <内容>` を足す。
2. **章仕様**: RX・EV・IR・CH に影響があれば直し、`## Clarifications` に `### Session YYYY-MM-DD (converge)` として記録する。
3. **正典**: `novelkit-canon` の「逆流」の手順（§5）で直す。新しい人物・用語はファイルを作る。
4. **伏線・筋の台帳**: 新しく張った伏線・開いた筋を足す。
5. **後続の章への影響**: 変えた事実に依存する後続の章を調べ、その章の `spec.md` の末尾に次を足す。次にその章を詰めるときの最初の論点にするためである。

   ```markdown
   ## 上流からの変更

   - YYYY-MM-DD <章>/<話番号>: <変わった事実>。<この章で確かめること>
   ```

   すでに C4（執筆）以降に進んだ後続の章は、書き換えずに影響を報告する。
6. **ネタ帳**: 本文から外したが惜しいもの（収束で除いた `unrequested` など）は、`docs/concept/backlog.md` に候補として残す。

## 6. 収束の確認

1. §2 の照合をもう一度行い、未解消のずれが 0 件になるまで §4・§5 を繰り返す。未完了の `[人]` の話のずれは、数えない。
2. `check.py --chapter <章>` を実行し、ERROR を 0 件にする。
3. 結果を `chapters/<章>/reviews/converge-YYYY-MM-DD.md` に保存し、`C9` のチェックポイントを記録する。

## 7. 完了報告

- ずれの件数（種類別）と、収束・逆流の内訳
- 逆流で変えた正典と章仕様、後続の章への影響
- ネタ帳に足したもの
- 次の案内: `novelkit-review <章> recheck`（C10）
