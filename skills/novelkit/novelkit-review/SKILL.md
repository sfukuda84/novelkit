# novelkit-review スキル（C5〜C8・C10: 4 軸レビュー）

出版の編集は、大きい問題（構成）から小さい問題（表記）へ進む。表現を磨いた後に構成を直すと、磨いた分が無駄になる。そのため、**物語 → 整合 → 類似性 → 文章の順に回し、上の軸の CRITICAL・HIGH が 0 件になってから下の軸に進む。**

類似性軸を文章軸の前に置くのは、盗作のおそれが見つかれば、その箇所を書き直すことになるからである。書き直す文を先に磨いても、無駄になる。

進捗の記録、モード、文脈パック、作者の本文を守る規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 1. 引数

| 軸の指定 | ステップ | 内容 |
|---|---|---|
| `story` | C5 | 物語軸 |
| `consistency` | C6 | 整合軸 |
| `originality` | C7 | 類似性軸（盗作の確認） |
| `prose` | C8 | 文章軸 |
| `recheck` | C10 | C5〜C9 の修正の副作用を 4 軸で確かめる |
| `all` | — | 4 軸を順に（単独で使うとき。チェックポイントは記録しない） |
| （省略） | — | `novelkit.py state --chapter <章>` の `NEXT_STEP` に対応する軸 |

話番号・範囲の指定がなければ、章の本文がある話すべてを対象にする。

## 2. 重大度

| 重大度 | 基準 |
|---|---|
| CRITICAL | 文体の決まりの MUST 違反。必須イベントが本文にない。伏せる名前の早漏れ。正典と矛盾する事実（年齢・生死・関係）。実在の人物を特定できる形で損なう描写。**既存作品と表現が一致する文**（類似性軸） |
| HIGH | 話の「変わること」が起きていない。引きがない。視点の漏れ。知識状態の矛盾。読者が話を見失う箇所。約束が裏切られる（進展も説明もなく消える）。**特定の既存作品と、特徴的な展開の組み合わせが重なる**（類似性軸） |
| MEDIUM | テンポの停滞、説明台詞、時間を要約で畳んだ箇所、口調のずれ、表記の揺れ、時代錯誤、文体の決まりの SHOULD 違反。**同じ題名の既存作品がある**（類似性軸） |
| LOW | 言い回しの改善、細かな表記 |

**字数について**: 文体の決まりの 1 話の字数（SHOULD）は、`check.py` が INFO（±10% の幅に収まる）を出したものは満たしたとみなす。範囲を大きく外れたもの（WARN）も、字数を追って言葉を足したり削ったりしない。**場面が足りないのか、多すぎるのかを物語軸で判断し、足りない場面・要らない場面として直す。**

## 3. 各軸の観点

### 物語軸（story）— ストーリー性

**読み手**: 正典・シーン台帳・章仕様を**渡さない**サブエージェント（Claude Code なら Agent ツール）。

- 渡すもの: それまでに公開した本文（章の最初から、対象の話まで）と、作品のジャンルと想定読者（`premises.md` の N2・N3 の 1 行ずつ）だけ。前の章は要約（`summaries.md`）で渡してよい。
- 役: `~/.myai/sparring/agents/novelist-*.md` のうち、ジャンルに合うもの。あれば、その定義を読ませて役を与える。
- サブエージェントには、**本文以外のファイルを開かない**ことを明示する。作品のディレクトリの設定・台帳を読むと、設定を知らない読み手ではなくなる。
- サブエージェントを使えない環境では、自分で行う。その場合は、本文以外の成果物を読む前に物語軸を済ませ、読み手として感じたことを先に書き出す。

読み手に答えさせること:

1. 話ごとに、読み終えた時点で**何を知っていて、何を予想し、何を期待しているか**（次の話を読む前に書き留めさせる）
2. 読むのをやめたくなった箇所と、その理由
3. 分かりにくかった箇所（誰が話しているか、どこにいるか、なぜそうしたか）
4. 心が動いた箇所と、動かなかった山場
5. 次の話を読みたいか（引きの強さを 5 段階で）
6. この話は結局、何の話だったか（一文）
7. 良い点（守るべきもの）。推敲で壊さないために、指摘と同じ精度で答えさせる

親（このスキル）は、答えを次と照合して指摘にする。

| 照合する相手 | 見ること |
|---|---|
| 章仕様の RX（読者体験）の受入基準 | 読み終えた読者の状態が、仕様どおりか |
| シーン台帳 | 「変わること」「価値」「シーン／シークエル」「引き」が、読み手に伝わっているか |
| 約束の台帳 | 約束が進展しているか。忘れられていないか |
| ジャンルの約束事と必須シーン（N3） | 満たしているか |
| 離脱の原因（Web 連載の場合） | 設定の詰め込み過ぎ、主人公に共感できない、物語の向かう先が見えない、読みにくい文章、引きがない、想定読者とのずれ。とくに章の最初の数話 |

読み手が挙げた「良い点」は、レポートの「守るもの」に書き、以降の軸の修正で壊さない。

### 整合軸（consistency）— 方向性・全体プロットとの整合

**読み手**: 自分（正典・台帳・調査資料をすべて使う）。話ごとに文脈パックを組み立てて読む。

| 観点 | 照合する相手 |
|---|---|
| 方向性と全体プロット | `direction.md` の中心の考え・読後感、`synopsis.md` の 5 文、`structure.md` のビートと目的の層 |
| 章仕様 | EV・IR・CH が本文にあるか |
| シーン台帳 | 箱・柱・登場・伏線・筋のとおりか。台帳と違う箇所は、`draft-notes.md` にあるか |
| 正典 | 年齢・日付・季節、人物の外見・口調・呼び方、場所、世界の規則、用語 |
| 状態 | 前の話の終了時点の状態（`state.md`）から、つながっているか。負傷・所持品・居場所など |
| 知識状態と開示 | 視点人物が知り得ないことを知っていないか（数や年齢の勘定の前提も含む）。伏せるものが漏れていないか |
| 事実と考証 | `docs/research/deep/` の事実、`anachronism.md` の語と物 |
| 実在モデル | `deep/real-models.md` の判定を守っているか |

`check.py --chapter <章> --only structure,canon,reveal,promises,threads` の結果も材料にする。前の軸（物語軸）の修正で生じた副作用（削った描写への参照、視点のずれ）も、ここで確かめる。

### 類似性軸（originality）— 盗作の確認

**読み手**: 自分。Web 検索（WebSearch / WebFetch）を使う。

盗作（著作権の侵害）になるのは、既存の作品に**依拠**して、その**表現上の本質的な特徴**を感じ取れる作品を作った場合である。アイデア、事実、作風、ありふれた構成（「繁栄 → 衰退 → 再生」のような型）は保護されない（文化庁『著作権テキスト』、江差追分事件・最判平成 13 年 6 月 28 日）。AI が書いた本文は、学習した既存作品の文を再現してしまうことがあるため、**表現の一致を検索で確かめる**。

#### 検索の予算と順序

- **1 章の検索の目安**: 表現 20〜30 件、展開 5〜8 件、題名・固有名詞 2〜5 件（計 30〜40 件）。Web 検索には、環境ごとに回数の上限がある（Claude Code では 1 セッションの上限を、調査の工程と共有する）。**始める前に `python3 <skills>/novelkit-status/scripts/novelkit.py budget --step C7` を実行し、STOP なら始めずに止まる**（`novelkit-status` §3「セッションの区切り」）。
- **害の大きいものから検索する。** 次の順に行い、上限に当たったときに、重要なものが未検索で残らないようにする。
  1. 各話の最後の一文
  2. 印象的な台詞（物語軸の「守るもの」に挙がった台詞を含む）
  3. 比喩（「〜のような」「〜みてえに」）
  4. 展開の検索（wide.md の重なりが大きい作品を含む）
  5. 作品の題
  6. そのほかの特徴的な地の文
- **上限に当たったら**: 検索を止め、未検索の語をレポートの「未完了」に一覧する。**C7 のチェックポイントは記録しない**（§4 の手順 6）。通常モードでは作者に、自動モードでは完了報告で、上限を上げるか新しいセッションで続けるよう伝える。検索エンジンの結果ページを WebFetch で開いて上限を避けることはしない。

#### 手順

1. **検索の候補を抜き出す。**

   ```bash
   python3 <skills>/novelkit-review/scripts/phrases.py --chapter <章> --per-episode 8 --out chapters/<章>/reviews/originality-phrases.md
   ```

   一覧は、上の「順序」に沿って並ぶ。各話の最後の一文・台詞・比喩を先に、そのほかの特徴的な文を後に置く。展開の検索用に、要約・題名・人物名・舞台も出る。スクリプトが拾わない印象的な文（物語軸の「守るもの」など）は、手で足す。読者の記憶に残る文ほど、既存作品と重なったときの害が大きい。

2. **表現の検索（完全一致）**: 一覧の各文を、引用符で囲んで検索する。
   - 長い文は、文の中の特徴的な 12〜20 字を切り出して検索する。
   - **Web 検索は完全一致に絞りきれない。**「一致なし」は「上位 10 件の結果（題名と抜粋）に、同じ文・ほぼ同じ文がない」という意味で記録する。
   - 抜粋に近い文が出たら、そのページを WebFetch で開いて確かめる。投稿サイトや書誌データベースのサイト内検索は、そのサイトの利用規約の範囲で使ってよい。
   - 一致・ほぼ一致が見つかったら、その出典（作品名、作者、該当箇所の URL）を開き、前後の文脈を確かめる。
   - 慣用句・ことわざ・当時の決まり文句（例: 「玉や」「鍵や」）の一致は、問題にしない。
   - 検索した文と結果（一致なし／一致あり）を、レポートの表に 1 件ずつ残す。

3. **展開の検索**: 要約と設定から、主人公の立場・目的・障害・結末の組み合わせを 3〜5 語の検索語にして検索する。
   - 例: `盲目 花火師 弟子 最後の玉 小説`、`師匠 嘘 弟子 花火 結末`
   - 小説に限らず、漫画・映画・ドラマ・ゲーム・Web 小説（投稿サイト）も対象にする。
   - `docs/research/wide.md` の「重なりが大きい作品」は、必ず照合の対象にする。あらすじ・レビュー・紹介文で、本作の話ごとの展開と比べる。
   - 筋を確かめられない作品（あらすじが公開されていない、など）は、判定を「保留」にする。確かめられた範囲で重なるのが構図までなら「型の共有」として扱う。結末や核まで重なる疑いがあれば「HIGH（保留）」とし、作者に確かめる（自動モードでは止まる）。
   - 新しく見つかった類似作品は、`wide.md` に日付つきの節（「類似性軸の追加調査」）として足す。

4. **題名・固有名詞の検索**: 作品の題（仮題を含む）と、主要人物の名前の組み合わせを検索する。話の題は、一般の語（例: 「川開き」）なら検索しない。固有の言い回しの話の題だけを検索する。

5. **判定する。**

   | 判定 | 基準 | 重大度 |
   |---|---|---|
   | 表現の一致 | 既存作品の文と、同じ、またはほぼ同じ文がある（語順・語の置き換え程度の違い）。慣用句・決まり文句を除く | CRITICAL |
   | 特徴的な展開の組み合わせの一致 | 特定の 1 作品と、ありふれていない展開・設定・人物の配置が**複数**重なり、その作品を知る読者が「あの作品だ」と感じる | HIGH |
   | 題名の一致 | **作品の題**が、同じジャンル・媒体の既存作品と同じ（題名は著作物ではないが、読者が取り違える）。話の題の一致は問題にしない | MEDIUM |
   | 型の共有 | ジャンルの約束事、トロープ、ありふれた構成が共通するだけ | 問題にしない（レポートに「型の共有」と書く） |
   | 一致なし | 検索で一致する作品が見つからない | — |

   - 判定の根拠（どの作品の、どの部分と、何が重なるか）を必ず書く。
   - **AI の判定は一次のふるい分けであり、法的な判断ではない。** CRITICAL・HIGH は、作者（通常モード）か専門家に確かめるよう、完了報告に書く。

6. **直す。**
   - 表現の一致: その文を書き直す。**言い換えで済ませず、その場面で視点人物が見たもの・感じたものから書き直す**（元の文の骨格が残ると、類似が残る）。
   - 展開の組み合わせの一致: 重なっている要素のうち、作品の核でないものを変える。核（中心の考え・結末）が重なる場合は、`novelkit-converge` で章仕様から見直す。
   - 題名の一致: 題名の案を出す（`novelkit-publish` で決める）。
   - **自動モード**: 表現の一致（CRITICAL）が見つかったら、書き直してから、もう一度同じ手順で検索する。書き直しても一致が残る、または展開の組み合わせの一致（HIGH）で核が重なる場合は、**止まる**（`novelkit-status` §4「自動モードでも止まる場面」）。

7. **限界を書く。** Web 検索で見つからないことは、類似作品がないことの証明にならない。書籍の本文の多くは検索できない。レポートの末尾に、検索した範囲（検索語の数、媒体、検索できなかったもの）を書く。

8. **完了の条件**: 次を満たしたときだけ、C7 を完了にする（チェックポイントを記録する）。
   - 順序の 1〜5（最後の一文・台詞・比喩・展開・作品の題）をすべて検索した
   - 表現の検索が、1 章の目安（20 件）以上ある
   - CRITICAL と HIGH（保留を含む）が 0 件
   満たさないときは、レポートの状態を「未完了」にし、記録しない。

### 文章軸（prose）— 誤字脱字・表現・論理構成

**読み手**: 自分（文体の決まり、`glossary.md`、口調の早見表を使う）。まず次の機械検査を実行し、その結果を材料にする。

```bash
python3 <skills>/novelkit-check/scripts/check.py --chapter <章> --only prose,glossary,length --metrics
```

| 観点 | 見ること |
|---|---|
| 誤字・脱字・衍字 | 変換の誤り、同音異義語、送り仮名、助詞の誤り、ら抜き言葉、敬語の誤り |
| 表記 | `glossary.md` の正表記とルビ（「初出のみ」の語は、初出で振っているか）、文体の決まりの表記の方針（数字・記号・ルビ・段落・場面の区切りの数） |
| 文体の決まり | 人称・時制・常体／敬体の混在、禁止事項 |
| 視点 | 視点人物のぶれ、一人称で知り得ない内面の描写 |
| 口調 | 早見表の一人称・二人称・語尾・呼び方。**物語軸の「守るもの」に挙がった言葉づかいの変化は揃えない** |
| 表現 | 冗長・重複、同じ語の近接（数文以内に同じ語が出る）、文末の単調、説明台詞、紋切り型 |
| 論理構成 | 文と文、段落と段落のつながり。理由と結果の順序。指示語の指す先。動作の順序と位置関係 |
| 声 | 声のサンプルの指標（台詞の比率、平均文長）から大きく外れていないか |

### 再レビュー（recheck）

C5〜C9 の修正差分（`git diff <C4 のチェックポイント>..HEAD -- <本文>`）を対象に、次を確かめる。

- 修正で生まれた新しい矛盾（整合軸）。とくに、描写を削った修正の後に、削った描写を前提にした文が残っていないか。書き足した修正が、後の話の発見を先取りしていないか
- **修正で書き足した文・書き直した文の、表現の一致**（類似性軸。§3 の手順 2 を、差分の文だけに行う）
- 修正箇所の前後の文のつながり（文章軸）
- 修正で引きや山場が弱くなっていないか（物語軸）。差分が大きい話は、**新しい**物語軸の読み手（前回とは別のサブエージェント）にもう一度読ませる

## 4. 手順（各軸に共通）

1. 対象の話と、その軸の読み手と材料を決める（§3）。
2. レビューし、指摘を重大度つきでまとめる。レポートは `chapters/<章>/reviews/<軸>-YYYY-MM-DD.md` に保存する（様式: [templates/review.md](./templates/review.md)。類似性軸は [templates/originality.md](./templates/originality.md)）。
3. 指摘の直し方を、次の 3 つに分ける。

   | 分類 | 扱い |
   |---|---|
   | 本文を直す | 本文の書き漏らし、誤り、表現の問題、既存作品との表現の一致 |
   | 逆流の候補 | 本文の方が台帳・正典より良い。C9 で扱うので、ここでは直さずに `draft-notes.md` に書く。修正で本文に新しい出来事・人物を足した場合も、`draft-notes.md` に書く |
   | 判断が要る | 作者に聞く |

4. 直す。
   - **通常モード**:
     - CRITICAL・HIGH は修正案を示して直す。
     - 本文が `status: 確定`、または `[人]` の話なら、修正案を示して了承を得てから直す。
     - MEDIUM・LOW は一覧を示し、直すものを選んでもらう（推奨案は「MEDIUM は直す、LOW は作者に任せる」）。
     - 判断が要るものは、推奨案（`**Recommended:**`）を添えて質問する。
   - **自動モード**: CRITICAL・HIGH・MEDIUM を直す。LOW は、**本文の数行の修正で直せて、ほかの箇所に影響しないもの**だけを直し、残りは一覧に残す。判断が要るものは推奨案を当て、`chapters/<章>/auto-decisions.md` に記録する。
5. 本文を直したら、`check.py --chapter <章>` を再実行し、ERROR を 0 件にする。直した話の要約・状態が変わったなら、`summaries.md`・`state.md` も直す。
6. 上の軸の CRITICAL・HIGH が 0 件であることを確かめてから、チェックポイントを記録する（C5・C6・C7・C8・C10）。指摘が 0 件でも記録する。**ただし C7（類似性軸）は、§3「類似性軸」の手順 8 の完了の条件を満たしたときだけ記録する。**

## 5. 完了報告

- 軸ごとの指摘の件数（重大度別）と、直したもの
- 物語軸: 読み手が答えた「知っていること・予想・期待」と、RX の受入基準との差。守るもの
- 類似性軸: 検索した文の数と、一致の有無。見つかった類似作品と判定。検索できなかった範囲。CRITICAL・HIGH があれば、作者か専門家に確かめるよう書く
- 逆流の候補（`draft-notes.md` に書いたもの）
- 作者の判断を待っているもの
