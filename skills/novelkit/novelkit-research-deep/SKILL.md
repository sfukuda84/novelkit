# novelkit-research-deep スキル（W5: 焦点調査・考証）

広域調査（W2）が題材の地図なら、焦点調査は**書くときに引く資料**である。プロットと設定の土台になる事実を、確からしさを付けて残す。

進捗の記録、モード、質問の規則は [`novelkit-status`](../novelkit-status/SKILL.md) に従う。

## 0. 大原則

- **出典のない事実を書かない。** 事実には出典、参照日、資料の種類（一次／二次）、確からしさ（高／中／低）を付ける。
- **一次資料**は「その時・その場で・その人が」残したもの（日記、書簡、公文書、当時の記録、当事者の証言）。**二次資料**は、それらをもとに後から書かれたもの（研究書、論文、解説、百科事典）。一次資料にも誤りや作為があるので、いつ・どこで・誰が書いたかを記録する。
- **調べる順序**:
  1. 辞典・事典で全体をつかむ
  2. 研究書・概説書
  3. 論文（CiNii Research、国立国会図書館サーチなど）
  4. 刊行史料・デジタルアーカイブ（国立国会図書館デジタルコレクション、ジャパンサーチなど）
  - 海外の題材なら、同じ種類の資料を現地の機関で探す。
- **資料の種類の区分**: 「一次」「一次（引用経由）」「二次」の 3 つにする。一次資料の文言を、研究書・解説・個人サイトの引用や転載で読んだ場合は「一次（引用経由）」と書き、引用元を併記する。
- **本文を読めない研究書**は、書誌（著者・書名・出版社・年）だけを記録し、「未読（書誌のみ）」と書く。根拠にはしない。
- **Wikipedia は入口にとどめる。** 参照したら版（更新日時）を記録し、同じ事実を別の資料で確かめる。確かめられなければ、確からしさを「低」にする。
- **架空の世界でも調べる。** 異世界でも、戦・医療・農業・交易・馬・天候など、現実の知識が下敷きになる部分は、現実の資料で裏を取る。

### 始める前に（検索の予算）

`python3 <skills>/novelkit-status/scripts/novelkit.py budget --step W5` を実行する（単独で題目を 1〜2 個だけ調べるときは `--need <見積もり>`）。STOP なら始めずに止まり、新しいセッションで実行するよう案内する（`novelkit-status` §3「セッションの区切り」）。

## 1. 題目の決め方

引数に題目があれば、それを調べる。なければ次から作る。

- `premises.md` の N3（ジャンルと約束事）、N9（分量と構成）、N10（世界の核）
- `wide.md` の「B. 現実の事例・歴史」で、W5 で確かめる対象にしたもの
- `seed.md`・`direction.md` の舞台（時代・場所）
- 執筆中なら、その話のシーン台帳と、レビューの指摘

題目は 3〜8 個に絞る（`real-models.md` と `anachronism.md` になる題目も数に含める）。題目ファイルのスラッグは、題目を英訳した英小文字のケバブケース 2〜4 語にする（例: `edo-fireworks-craft`）。通常モードでは、題目の一覧を示して、追加・削除を確かめる。

## 2. 手順

### ステップ 1: 題目ごとの調査

各題目について `docs/research/deep/<題目のスラッグ>.md` を作る（様式: [templates/deep.md](./templates/deep.md)）。

1. 調べる問いを、書く場面に即して立てる（例: 「冬の遊牧民は 1 日に何回、何を食べるか」「縫合に使った糸の材料は何か」）。
2. §0 の順序で調べ、事実を 1 件 1 行で記録する。
3. 資料どうしで食い違う点は、両方を書き、どちらを採るかと理由を書く。
4. **物語に使える具体**（五感の細部、道具の名前、手順、当時の言い回し）を別の欄に集める。書く場面の手触りになる部分である。
5. **史実と創作の境目**を書く。作品で変える点、変えない点、変える理由。

### ステップ 2: 時代錯誤の一覧

`docs/research/anachronism.md` に、その時代・世界にまだない、または違うものを挙げる。

- 対象: 道具・技術、言葉と言い回し、制度、食べ物、単位、価値観
- 各項目に、正しい代わり（その時代の言い方・道具）と出典を書く。
- この一覧は、整合軸のレビュー（`novelkit-review`）で、本文を照合する辞書として使う。
- 異世界の作品では、「この世界にないもの」（例: 火薬、時計、特定の外来語）の一覧として使う。

### ステップ 3: 実在の人物・団体・事件の点検

`wide.md` や題目に、実在の人物・団体・事件が関わる場合は、`deep/real-models.md` に次を点検して書く。

| 観点 | 点検すること |
|---|---|
| 特定できるか | 名前を変えても、経歴・場所・出来事の組み合わせから本人を特定できないか |
| プライバシー | 描く内容が、①私生活上の事実か、事実らしく受け取られるおそれがある、②一般の人の感覚で公開を望まない、③まだ一般に知られていない、に当たらないか（「宴のあと」事件の 3 要件） |
| 名誉 | 社会的な評価を下げる描写が、公共の利益と関わりなく含まれていないか。公的な立場にない人を、特定できる形で侮辱的に描いていないか（「石に泳ぐ魚」事件） |
| 注記 | 「この物語はフィクションです」の注記だけでは免責されない前提で判断する |

- 判定は **低 / 中 / 高**（リスク）で書き、中・高なら、変える案（人物の合成、時代・場所の移動、出来事の組み替え）を示す。
- **高と判定したら、自動モードでも止まる**（`novelkit-status` §4）。法的な判断が必要なら、専門家への相談を勧める。AI の判定は一次のふるい分けであり、最終判断ではない。

### ステップ 4: 前提との食い違い

調査の事実が、確定済みの前提（`premises.md`）と食い違う場合:

- **自動モード**: `premises.md` の該当項目を考証に合わせて直し、`#### Q<n>（考証, auto）` として質疑記録に残す。`docs/auto-decisions.md` にも記録する（見直しの優先度: 中。結末や主人公に関わるなら高）。
- **通常モード**: 食い違いと直し方の案を示し、作者の判断を得てから直す。

### ステップ 5: 提示

題目ごとの要点、時代錯誤の件数、実在モデルの判定を示す。

- **通常モード**: 追加で調べる題目を確かめる（「このまま W6 へ」を推奨案にする）。
- **自動モード**: 追加の調査はしない。確からしさが「低」の事実と、実在モデルの判定が「中」のものを `docs/auto-decisions.md` に記録する（見直しの優先度: 中）。

## 3. 出力

- `docs/research/deep/<題目>.md`
- `docs/research/anachronism.md`（様式: [templates/anachronism.md](./templates/anachronism.md)。既存の項目は消さず、足す）
- `docs/research/deep/real-models.md`（実在の人物・団体・事件が関わる場合）

Web を調べられない環境では、調べるべき項目と理由を「未調査」として書き、推測で埋めない。

W5 として実行したときは、終わったら `W5` のチェックポイントを記録する。執筆中に単独で実行したときは、チェックポイントを記録せず、通常のコミットにする。

## 4. 完了報告

- 題目ごとの要点と、物語に使える具体の例
- 確からしさが「低」の事実
- 時代錯誤の件数
- 実在モデルの判定（あれば）
- 次の案内: `novelkit-constitution`（W6）
